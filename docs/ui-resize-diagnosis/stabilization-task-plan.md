## 约束与决策
- 不修改数据库。
- 不改动用户现有未跟踪文件，除非它们属于本任务已有诊断材料。
- 不提交、不推送，除非用户另行要求。
- resize 修复不得直接依赖未经封装的 JLine 私有反射字段，除非确认没有稳定公开接口且有兼容保护。
- resize 只走 `LineReaderImpl.handleSignal(WINCH)` 这一条同步路径，不使用轮询或反射。
- 活动读取期间不发送 ANSI CPR、不从终端输入流查询光标；窗口变化时清除回流残影并重放 ACode 已提交对话。
- 输入框五层统一放在固定高度的底部状态区；多行输入从预留空白向上展开，不在每次换行时改变滚动区域。
- 读取期间发生 resize 后，进入读取前按旧尺寸得到的钉底回退量必须作废。
- 第五版单行方案和第六版多行 JLine 提示符都已被真机否定。当前方案采用 JLine 3.30.16 维护按键编辑，底部状态区绘制完整输入框。
- 用户选择 CMD 保留鼠标拖选复制；原生滚轮查看旧视口时输入框随整个视口移动，滚回最新画面后贴底。

## Errors Encountered
| Error | Attempt | Resolution |
|---|---:|---|
| 受限沙箱运行全量测试产生 43 failures / 8 errors | 1 | 在正常本机权限下重跑，确认真实基线为 1118 tests、1 failure、1 skipped |
| JShell 无法写 Windows Preferences 注册表而退出 | 1 | 放弃该探针，直接从失败值 `C:` 与 `SystemDrive`/`SYSTEMDRIVE` 大小写差异定位根因 |
| resize 定向测试在受限沙箱中触发 5 failures / 2 errors | 1 | 与既有路径沙箱症状一致；改在正常本机权限下重跑同一组测试 |
| Codex 内置命令 PTY 缺少光标上移/清屏能力，ResizeProbe 拒绝启动 | 1 | 需要在真实 Windows 终端窗口中执行探针完成视觉验收 |
| 新开的 cmd 仍被判定为不支持活跃区绘制 | 1 | 查明其继承了 Codex 的 `TERM=dumb`；清空 TERM 后重新启动真实控制台 |
| 真机 resize 出现 CPR 控制序列进入输入、重复框线和布局错乱 | 1 | 活动 `readLine` 与 CPR 共用输入流产生竞争；撤销“活动期 ANSI CPR”假设，改用不读取输入流的光标定位方案，并补能复现响应竞争的测试 |
| 第二版真机缩小时页眉重复、放大时输入区高度失控 | 2 | JLine 内部 WINCH 与 120ms watcher 形成两条重绘链；移除 watcher，把动态 prompt/重锚定合并进 `LineReaderImpl.handleSignal` 的单一串行路径 |
| 第三版真机连续缩放仍出现阶梯状重复页眉 | 3 | 应用先移动真实光标，JLine 随后按旧 Display 光标模型重绘；且提示符高度只统计换行，未覆盖缩窄后的物理折行。第四版取消活动期外部光标移动，优先保证单一所有者与内容稳定 |
| 第四版真机仍连续输出模式行与分隔线 | 4 | 即使无应用层光标移动，JLine 3.27.1 的 Windows 回流路径仍无法稳定维护多行 prompt + Status；停止修补坐标，改为单行 prompt 架构 |
| 第五版单行方案与用户指定的五层输入框不符 | 5 | 恢复三行提示符，改用缩放时重建 Display 的 JLine 3.30.16，并以真机验收决定是否保留 |
| 第六版真机拖拽仍留下多份模式行和上边线 | 6 | 放弃让多行 JLine prompt 承担固定框绘制；保留 JLine 编辑能力，另建统一绘制层并验证滚动回看取舍 |
