## 默认值说明（实现与测试必须与此一致）

**ACODE.md 加载**

- 三层顺序（高优先级在前）：`<项目根>/ACODE.md` → `<项目根>/.acode/ACODE.md` → `~/.acode/ACODE.md`；文件不存在即跳过
- 拼接：三层**内容拼接**（不覆盖），分隔线固定为 `\n\n----\n\n`
- `@include` 语法：**整行匹配** `@include <路径>`（行首允许空白，本行不得有其他内容）；路径**相对被引文件所在目录**解析

**`@include` 安全边界**

- 深度上限：`5`（顶层指令文件为第 1 层，即最多再展开 4 层）
- 已展开集合：canonical real path 集合；同一文件被引用多次只展开一次（A↔B 环由此自然终止）
- 项目级来源（项目根两处）的引用：解析后的 canonical 真实路径必须 `startsWith` 项目根 canonical，否则拒绝展开
- 用户级来源（`~/.acode/`）的引用：解析后必须 `startsWith` 用户主目录 canonical，否则拒绝展开
- 符号链接按 canonical 真实路径判定（不能靠 `..` 前缀比对绕过）
- 跳过/拒绝**一律不抛错、不中断启动**，只产出一行告警并可继续
- 单个被展开文件体量上限：`64_000` 字符；超出截断并附 `…（内容过长，已截断）`

**注入位置**

- 段优先级：Identity `0` → **项目指令 `5`** → **记忆索引 `7`** → Behavior `10` → …（既有七段不动）
- 空段不出现在 system 提示里；三层指令全缺失 + 无记忆时，system 提示与阶段七输出逐字相同（无回归）
- 注入时机：**会话启动构建一次，会话内字节不变**；异步提取写入的新记忆**下个会话**才出现在提示里

**会话存储**

- 目录：`<项目根>/.acode/sessions/`；扩展名 `.jsonl`
- 会话 id：`yyyyMMdd-HHmmss-` + 4 位小写十六进制随机串；文件名即 id；同一秒内连建多个会话不碰撞
- 行格式：一行一个 JSON 对象，字段 `role` / `content` / `ts`；`content` 可为纯字符串或块数组；`ts` 为整型 Unix **秒**
- `ts` 语义 = 落盘时刻（追加时打戳）；会话的"最后活跃时间"取该文件**末行** `ts`
- 解析失败的行**直接跳过**（含进程被杀留下的半行）；文件缺失/为空/全部行非法 → 按空会话处理，不抛错
- 空会话**不创建文件**；首次追加消息时才创建
- 追加顺序：**先写盘、再更新内存**；写盘异常只记告警并继续本轮对话（内存仍更新），不中断、不重试
- 退出路径（`/quit`、EOF、Ctrl+C）：关闭句柄；**不再整存、不新建文件**
- 整段重写（压缩后）：写同目录临时文件 → 逐行落盘 → 原子替换；重写失败保持原文件逐行不变
- 恢复：末行 `ts` 距现在 > `86_400` 秒（24h）→ 产出时间跨度提醒文本（含"上次会话时间"与"建议重新读取相关文件"语义）；该提醒作为**恢复后首轮的轮次提醒**注入，**不进历史、不落盘**，第二轮不再出现
- 恢复的历史若整体估算 ≥ 阶段七的自动压缩触发点 → 恢复时压缩一次（与 `/compact` 同一路径）
- 过期阈值：末行 `ts` 距现在 > `2_592_000` 秒（30 天）→ 列表条目标记 `（已过期）`，**排在最后，不删除**
- 列表排序：按末行 `ts` 降序（活跃在前），已过期项无论时间一律排在未过期项之后
- 加载某会话后：后续消息**追加进同一文件**（不新建、不产生副本）

**记忆存储**

- 用户级根：`~/.acode/memory/`（用户偏好 `user`、纠正反馈 `feedback`）
- 项目级根：`<项目根>/.acode/memory/`（项目知识 `project`、参考信息 `reference`）
- 两级各有自己的 `MEMORY.md` 索引；注入时**项目级索引在前、用户级在后**依次拼接（与 ACODE.md「项目级排在前」同序）
- 记忆文件名：`<type>-<slug>.md`；`slug` 匹配 `[a-z0-9][a-z0-9-]{0,39}`；含 `../`、绝对路径、非法字符一律拒绝写入
- 记忆文件头部字段：`name` / `description` / `type`；正文含 `**Why**：` 与 `**How to apply**：` 两行
- 索引行格式：`- [标题](文件名) - 摘要`
- 头部残缺 / `type` 非四类之一 / 文件不是 `.md` → 列表时跳过该文件并告警（不抛错）
- 索引上限：`200` 行 **或** `25 KB`（先到者生效）；超限截断并附加警告行 `（记忆索引超限，已截断）`
- 索引里指向不存在文件的悬空指针行：加载时忽略并告警，**不自动改文件**
- 项目级根不可写 → 降级为只写用户级并告警一行，不抛错、不阻断

**自动记忆提取**

- 触发点：每轮 Agent 循环到达 `NORMAL_END`（模型给出最终回复、不再调用工具）之后
- 执行方式：后台异步（应用级虚拟线程池），不阻塞下一轮对话；未装配记忆管理器时跳过
- 同一时刻最多 `1` 个提取任务；已有任务在跑时新的触发**跳过本轮**（不做排队、不累计）
- 提取输入 = 索引 + 现有记忆清单 + **最近一轮对话**（从最后一条 user 消息到历史末尾）
- 提取请求断言：`tools` 为空、`thinking` 为 false、`max_tokens` = 独立常量 `4_000`
- 模型输出：结构化操作列表（JSON 数组，元素含 `op`∈{create,update,delete} / `type` / `name` / `description` / `body`）；解析失败 → **本轮零文件写入**（不报错、不部分写入）
- 单项落盘失败 → 跳过该项并记日志，其余项照常
- 写回前校验会话代次：该轮已被 `/clear` 或加载会话作废 → 结果整体丢弃
- 提取失败（网络/超时/异常）→ 只记日志，**不向用户报错**、不影响后续对话
- 不设熔断（与阶段七摘要不同）：失败下轮照常再试

**配置与命令**

- 配置项 `memory_auto`：缺省为**开**；显式 `false` 关闭自动提取（关掉后无每轮后台模型调用）
- 关闭自动提取不影响 `/memory run` 手动入口
- `/help` 与 `/memory` 相关帮助文本包含 `/memory` 行
- `/memory`（无参数）输出：两级记忆条数 + 索引行数/体积 + 是否被截断
- `/memory run` 输出：新增/更新/删除条数；无可记忆内容时输出 `（没有值得记忆的内容）`；失败时输出原因且不写任何文件
- `/resume` 帮助文本说明"加载后继续写回该会话"
