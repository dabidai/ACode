# ACode 阶段九：Slash Command 命令框架 — spec

> 最后更新：2026-09-13
> 功能诉求见 `prompt.md`；本文只定"做什么/为什么"，不含函数名、参数名、默认值与错误文本；具体阈值与文案集中在 `checklist.md` 顶部
> 已确认的前置决策：Tab 补全**先做最小验证再定实现方案**；`/permission-mode` 改名 `/permission`（不留别名）、**`/resume` 保留并吞并会话管理**（`/session` 取消）、**命令形态统一为"无参=查看、带参=操作"**（`/memory` 与 `/permission` 照此重排，冗余子命令删除）；`/status` 的 Token **用上下文占用口径**（与 `/compact` 同源）；`/do` **有已交付计划则执行、无则仅切换模式**；权限规则效果**扩为放行/拒绝/询问三态**（**询问与拒绝同级跨层穿透**，且命中询问时先让既有「始终允许」过一遍再决定要不要问）；`/quit` 纳入框架并**保留为可见命令**

## 背景

ACode 的命令现在是"硬编码在几处的 if/switch"：

- **加一个命令要动三处**：路由层用一个枚举把输入归类，执行层用一个分支干活，带参数的命令还要在执行层再写一遍前缀匹配与参数截取。命令的"名字、参数、行为"散落在不同文件里，改一处要记得改另两处。
- **处理器拿不到依赖**：命令的实际逻辑写在主循环宿主类的方法里，靠实例字段访问会话、上下文管理器；每来一个新依赖（压缩、记忆），就加一个回调注入点与一个空实现的缺省值。命令与宿主类强耦合，宿主类持续膨胀。
- **没有元数据可用**：命令没有统一的描述/用法/别名，帮助文本是手写的一大段固定字符串，与实现分离、天然会过期；没有别名概念；没有"内部命令不展示"的概念；参数缺失时没有统一提示，只能每个命令自己写一句错误。
- **没有补全**：命令全靠背。
- **结构接不住下一章**：Skill 系统要在**运行期**注册新命令，届时注册与查找会并发发生。当前的静态分支结构无法承载动态注册。

本章把命令从"散落的分支"改造成**声明式注册 + 解析 + 统一执行**的框架，把现有命令全部迁移过去，并补上别名、参数提示、隐藏命令与 Tab 补全。

## 目标用户

- 本人：日常高频使用命令，希望少打字（别名 + 补全）、能看懂现有命令（元数据生成的统一帮助）、用错时被正确引导（而不是一句冷冰冰的报错）。
- 后续潜在使用者：第一次上手能靠帮助与补全自己发现能力边界。
- 下一章的 Skill 系统（内部消费者）：需要一个可运行期注册、并发安全的注册中心。

## 能力清单

### 一、命令定义与注册

1. **声明式注册**：命令以一条完整定义的形式注册进注册中心，定义包含——名称、别名列表、简短描述、用法示例、命令类型、参数用法说明、是否在帮助中隐藏、处理函数。注册即生效，不再需要分别改路由与分发两处。
2. **集中定义**：所有内置命令在同一处声明完毕，命令清单一眼可见。
3. **别名**：一条命令可声明多个别名，别名与正式名完全等价。
4. **冲突检测**：注册时即检测"名称已被占用""别名已被占用"，冲突当场报错，而不是等到运行时行为诡异。别名与某个已存在的正式名相同也算冲突。
5. **隐藏命令**：可标记为不展示，用于内部命令。隐藏命令仍可正常调用，但不出现在帮助列表与补全候选中。**本章没有内置命令使用它**——退出命令保持可见；机制本身保留，由注册中心的单测覆盖（测试里注册一条隐藏命令），留给下一章的 Skill 系统做内部命令。
6. **并发安全**：注册中心的读（查找、列清单）与写（注册）必须能被并发访问——本章所有命令在启动时注册完毕，但下一章的 Skill 系统会在运行期注册，届时注册与查找可能同时发生。读操作之间不互相阻塞，写操作独占。

### 二、解析

7. **命令与参数切分**：把一行输入按**首个空白**切成两部分——命令名与参数原文。命令名之后的所有内容都是参数，保留原始大小写与内部空白，不做引号解析、不做多参数结构化。
8. **名称大小写不敏感**：命令名统一转为小写后再查找；参数不受影响，大小写原样保留。
9. **非命令输入**：不以斜杠开头的输入不是命令，交给正常对话流程。
10. **空参命令**：命令名后带分隔空白但无内容，视同无参数。

### 三、执行

11. **统一处理函数签名**：所有命令的处理函数形参一致，所需的一切资源打包成一个上下文对象传入。处理函数不需要关心"怎么拿到会话/记忆/UI"，框架已备好。
12. **上下文内容**：上下文覆盖命令实际需要的一切——原始参数串、界面操作接口、权限、上下文管理、长期记忆、会话管理、当前工作目录、工具注册表、版本。**按需收录而非求全**：本章没有任何命令直接持有 Agent 或裸会话对象（提示词类命令经界面操作接口提交、压缩与状态经各自门面），这类依赖不进上下文，免得养出无人使用的空壳字段。
13. **命令类型**：三类（**类型只作元数据，用于帮助分组与说明，不产生不同的执行分支**）——
    - **本地命令**：纯本地执行，结果以系统消息形式显示，不触碰界面模式。
    - **本地界面命令**：本地执行，但会改变界面状态或交互模式（进入/退出规划模式、清空界面与历史）。
    - **提示词命令**：不在本地完成工作，只负责构造一段预设提示词交给 Agent 执行。
14. **界面操作接口**：界面层向命令暴露一组受控操作——追加一条系统消息、把一段文本当作用户输入发给 Agent、切换规划模式、读取当前上下文占用、弹出交互式选择菜单（供会话恢复与记忆菜单复用；记忆菜单要在三层指令文件与"查看长期记忆"之间画一条**不可选**的分隔行，故菜单支持纯分隔行——不高亮、不被上下键停留）。命令不直接操作终端对象。**不做本章没有命令使用的操作**：刷新状态栏由主循环自己维护，不进接口。
15. **命令失败不崩**：单个处理函数抛出异常时，框架捕获并以一行错误系统消息呈现，主循环继续，会话不受影响。
16. **执行结果可控**：处理函数需要能表达"本次执行后是否继续主循环"，使退出类命令无需绕过框架。

### 四、与输入循环集成

17. **回车分流**：输入非空时先判断是否为命令——是则走命令框架，不是则走 Agent 对话。
18. **空输入**：直接忽略，不做任何事。
19. **裸斜杠**：只输入一个斜杠、没有命令名时，列出全部可用命令（等同请求帮助）。
20. **未知命令的引导**：命令名查不到时，错误信息中必须包含指向帮助的引导语——**错误提示永远带引导**，不允许出现只报"命令不存在"就结束。
21. **参数不合法时的提示**：命令的参数无法被解释时（格式不对、可取值非法），展示**该命令自己的**用法提示——列出合法取值与各个分支，而不是笼统的"参数错误"或"缺少参数"。
22. **错误能自纠**：未知命令的提示应回显用户实际输入的命令名，让用户看出自己打错了什么。

### 五、Tab 补全

23. **斜杠触发**：输入以斜杠开头时，Tab 进入命令补全模式；否则不干预（交给输入组件的默认行为）。
24. **全部命令**：输入仅为斜杠时按 Tab，列出全部可用命令（隐藏命令除外）。
25. **前缀补全**：输入斜杠加前缀时按 Tab，按前缀过滤候选。
26. **单候选直接补全**：候选唯一时，直接把该命令名补全进输入框。
27. **多候选可视化**：候选多个时以列表形式呈现，同时展示命令名与描述，让用户看懂再选。
28. **补全后仍可编辑**：补全只改变输入框内容、不提交；用户可继续补参数或修改。

### 六、内置命令

29. **命令形态约定**：同一命令用"**有无参数**"区分**查看**与**操作**——不带参数一律是查看（列出/展示当前状态），带参数则是执行某个操作。少数无法用"有参/无参"区分的操作用**保留首词**承担。目标是让用户少记少打：想看现状就敲命令名，想做点什么就带上参数。
30. **帮助**：无参数时**按命令类型分三段**列出全部可见命令（命令名、别名、描述）；带命令名参数时给出该命令的详细用法（描述、用法示例、参数说明、别名）。帮助列表由注册中心的元数据生成，不再手写。
31. **压缩**：无参数执行标准上下文压缩；带参数时把参数作为"需要保留的重点"交给压缩流程。上下文占用低于阈值时直接提示无需压缩，不发起压缩。
32. **会话恢复**：不带参数时弹出交互式选择菜单，列出历史会话供选择并切过去。会话的**查看、新建、删除不做成命令**——菜单本身就是查看，新建与删除都不是高频动作，为此引入子命令层级不划算。
33. **指令文件入口**：无参数时弹出菜单，列出三层指令文件——项目根、项目本地、用户级——并标注各自是否存在；菜单末尾附一项"查看长期记忆"。选中某一层后输出该层的路径与内容；文件不存在则创建它（让用户级这种不好记的路径一键就位）。带保留词时立即触发一次长期记忆提取（沿用现有手动提取的语义）。
34. **长期记忆由 Agent 维护**：长期记忆（一记忆一文件 + 索引）**不做成命令族**——增、改、删都由 Agent 在对话中用文件工具完成（用户说"记住某事"时写入对应记忆文件并同步索引）。命令层只保留"查看"（挂在指令文件菜单里的一项）与"立即提取"。这样既绕开了命令层的编辑体验难题，也让手动写入与自动提取走同一条路径。
35. **权限**：无参数时**列举**——当前权限模式、三层规则各自的文件路径与条数、每条规则的内容与效果；带参数时**切换**权限模式（参数须为合法模式之一）。**规则本身只读**：新增、修改、删除都由用户直接编辑规则文件完成，不做成命令。规则的效果含**放行 / 拒绝 / 询问**三态——命中"询问"规则时不直接判定，而是穿透到人工确认环节。
36. **状态**：一屏展示综合状态——当前模式、上下文占用与上限及占比、已启用工具数、**四类记忆各自的条数**、工作目录、版本。
37. **清空**：当前对话保存后开启新会话，并清空界面。
38. **规划模式**：进入规划模式；带参数时同时把参数作为任务描述发给 Agent 开始规划。
39. **执行模式**：退出规划模式；若上一轮规划模式已交付一份计划，则把该计划作为任务发给 Agent 开始执行；没有则只切换模式并如实告知。
40. **审查**：构造一段预设的代码审查提示词发给 Agent，要求其分析当前工作区的未提交变更；带参数时把参数作为额外关注点并入提示词。
41. **退出**：保留退出能力，作为**可见命令**出现在帮助与补全中（无别名、不接受参数、不产生任何输出）。

## 非功能要求

- **零新增依赖**：注册、解析、补全全部使用 JDK 与既有输入组件能力；不引入命令解析库或补全框架。
- **逻辑层与终端解耦**：注册、查找、解析、别名解析、冲突检测都不依赖终端，可在无终端的单测里直接断言（沿用既有路由类"纯逻辑、便于单测"的风格）。
- **并发安全且读不互斥**：查找与列清单是高频读、注册是低频写；读读并发、读写互斥、写写互斥。
- **界面风格统一**：命令输出沿用既有约定——单行提示用全角括号包裹、帮助类列表等宽对齐、内容进原生回滚区可复制、状态变化如实告知用户。**配色分两步走**：本阶段先按现有约定落地，实现完成后**再对照 PR #2（`dabidai/ACode#2`）的 `ui/StatusBar.java` 做一次风格对齐**——那套 ANSI 色板（模式黄、模型青、进度条青、暗色辅助）是本项目已提交的配色出处，`/status` 与 `/help` 应对齐它而不是另立一套。**该 PR 不并入本阶段**：它的斜杠补全与 `/model` 命令不在本章范围内，内置命令清单维持本章定义。
- **不阻塞对话**：命令在主循环空闲态执行（与现状一致）；命令执行失败不中断主循环、不丢失会话。
- **错误文案可发现**：任何"用错了"的路径都必须给出下一步动作（指向帮助、给出用法或参数提示）。
- **能力只增不减，调用形态有六处变化**：本章对现有命令做重排而非删减。
  - **新增两个命令**：`/status`（综合状态）、`/review`（审查提示词）。
  - **形态变化六处**（用户已确认）：命令改名（`/permission-mode` → `/permission`）、会话命令收敛（`/session` 取消，恢复统一走 `/resume`）、`/memory` 重定义为指令文件入口（长期记忆的增 / 改 / 删由对话承担，`/memory run` 保留）、`/permission` 改为"无参=查看、带参=操作"（原 `/permission mode`、`/permission rules` 写法失效）、执行模式退出后**真的会执行已交付计划**（原来只切模式并输出一句不实的"开始执行"）、权限规则效果扩为三态（放行 / 拒绝的相对语义不变，询问与拒绝同级跨层穿透）。
  - **新增一处行为判断**：`/compact` 在上下文占用低于 5000 token 时直接提示无需压缩、不发起压缩。**现有实现没有这个判断**（`handleManualCompact` 无条件压缩），是本阶段新增的，别当成既有行为搬运。
  - **修复一处既有缺陷**：长期记忆文件对 Agent 的可及性——注入的索引只有文件名没有路径、沙箱只放行项目根与临时目录，用户级记忆根一律被拒（见上表）。**注意**：`/do` 那条（上表形态变化第 ⑤ 项）本身也是修缺陷——原实现输出"开始执行"却只切了模式（`CommandProcessor.java:100-104`），但它是同一处改动，不另计一次。
  - README 命令表与手测文档同步更新。

## 设计骨架

### 分层

```
┌────────────────────────────────────────────────────────────────────┐
│  输入循环                                                          │
│  回车 → 空？忽略 │ 命令？→ 调度器 │ 否则 → Agent 对话              │
│  Tab  → 斜杠开头？→ 补全器                                         │
├────────────────────────────────────────────────────────────────────┤
│  命令调度器                                                        │
│  解析（名 + 参数、名小写）→ 查找（正式名 → 别名）→ 建上下文 → 执行 │
│  查不到 → 错误 + 指向帮助 │ 参数不合法 → 用法提示                  │
├────────────────────────────────────────────────────────────────────┤
│  注册中心（读写锁）                                                │
│  注册（冲突检测）· 查找 · 可见清单 · 补全候选                      │
├────────────────────────────────────────────────────────────────────┤
│  内置命令定义（声明顺序即展示顺序）                                │
│  local：help compact resume memory permission status quit          │
│  local-ui：clear plan do                                           │
│  prompt：review                                                    │
│  （本章无内置隐藏命令，hidden 机制留待下一章）                     │
├────────────────────────────────────────────────────────────────────┤
│  命令上下文（打包依赖，只收有人用的）                              │
│  参数 · 界面操作接口 · 权限 · 上下文管理 · 记忆 · 会话管理         │
│  工作目录 · 工具注册表 · 版本                                      │
└────────────────────────────────────────────────────────────────────┘
```

### 一次输入的执行流

```
用户输入 ─┬─ 空 ───────────────────────────→ 忽略
          ├─ 以斜杠开头 ─→ 解析 ─→ 查找 ─┬─ 命中 ─→ 建上下文 ─→ 执行
          │                              ├─ 参数不合法 → 用法提示
          │                              └─ 未命中 → 错误（含 /help 引导）
          └─ 其他 ─────────────────────────→ Agent 对话
```

### 三类命令的执行路径

```
local      本地执行 ─→ 结果作为系统消息提交到输出区
local-ui   本地执行 ─→ 改变界面/交互状态（规划模式开关、清空与新建会话）
prompt     本地构造预设提示词 ─→ 交 Agent 执行（走既有对话入口）
```

**类型是元数据，不是执行分支**：三类命令的处理函数签名完全相同，都通过界面操作接口产生效果，框架不对类型做 switch 派发——分类只决定它在帮助列表里落在哪一段。

### 补全流

```
输入以 "/" 开头 ─→ Tab ─→ 取可见命令清单 ─→ 按前缀过滤
                                          ├─ 0 个 → 无操作
                                          ├─ 1 个 → 直接补全进输入框
                                          └─ 多个 → 列表呈现（名称 + 描述），可继续选择
```

## 关键设计决策

| 决策点 | 结论 |
|---|---|
| Tab 补全实现 | **结论：走既有输入组件的内建补全**（2026-09-13 真机验证，风险前置完成）。既有内建补全默认行为是在输入行下方自绘候选并循环选择，**不是**下拉菜单；以其与主屏渲染模型（活跃区重绘 + 原生回滚 + 接受输入时擦行）的交互无先例，故先用最小补全器（硬编码候选）在真实终端验证，观察到：① 仅斜杠按 Tab 列出全部可见命令；② 唯一前缀直接补全进输入框（`/com` → `/compact`）；③ 多候选自绘列表呈现、可循环、接受后输入行干净无错位；④ 补全后继续输入参数正常；⑤ 补全后 Esc / Ctrl+C，输入行与活跃区清理正常；⑥ **原生回滚区无候选列表残影**（关键项，无冲突）。附带澄清：Esc 保持既有输入组件的默认语义（meta 前缀键，单独按不清空输入缓冲），`InputPane` 本就只绑定回车与 Shift+Enter，与补全无关，不属冲突也不在本章修。因此 T11 沿用内建路线，**不需要**自定义下拉组件。 |
| 命令命名 | **`/permission-mode` 改名为 `/permission`**（不留别名，用户已确认）。**`/resume` 保留并吞并会话管理**（用户已确认）：`/resume` 只做"弹菜单选择恢复"；会话的**查看、新建、删除不做成命令**，`/session` 取消。理由：菜单本身就是查看，新建与删除都不是高频动作，为此多保留一层子命令层级不划算。 |
| 命令形态 | **统一为"无参=查看、带参=操作"**（用户已确认）：`/permission` 无参列举、带参切档。命令名已足够表意，再让用户记"哪个操作配哪个子命令"是多余负担。原 `/permission mode`、`/permission rules` 等写法随之下线。`/memory` 与 `/resume` 的无参形态是**弹菜单**（菜单本身就是一种查看），同样不引入子命令。 |
| 保留首词 | 命令用保留首词承担少数无法用"有参/无参"区分的操作，判定顺序固定为：**保留首词 → 合法取值 → 否则按参数提示处理**。全章只有一处：`/memory run` 判为立即提取一次长期记忆（而不是当成内容参数）。**权限命令没有保留词**——它的规则是只读的。 |
| 权限规则只读 | **规则的增 / 改 / 删不做成命令**（用户已确认）：`/permission` 只负责"看"（列举模式与三层规则）与"切档"，规则由用户直接编辑规则文件完成。理由：规则是 `工具名(模式)` 的精确模式，手写比命令行拼更清楚也更好改；规则文件本来就是三级 YAML，用户已有直接编辑的习惯。代价是 `/permission` 的无参列举**必须显示三层的文件路径**，否则用户不知道去哪改。 |
| 记忆入口的拆分 | **`/memory` 管指令文件，长期记忆交给 Agent**（用户已确认）。`/memory` 无参弹菜单，列出三层指令文件（项目根 / 项目本地 / 用户级）并标注存在与否，选中后输出路径与内容、不存在则创建；菜单末尾附"查看长期记忆"一项。长期记忆的**增 / 改 / 删全部经对话由 Agent 用文件工具完成**——命令层不做 `add` / `del` / `clear`，也不做"选作用域"菜单。理由：长期记忆是"模型在对话里发现值得记的事"，天然入口就是对话；给它配一套命令族是拿命令行模拟对话，且模拟不全（改一条就得内置编辑器）。 |
| 长期记忆的可及性 | 上一条要成立，必须先修两处 **ch08 遗留缺口**：**① 索引注入里只有文件名、没有路径**，Agent 不知道该去哪读写；**② 路径沙箱只放行项目根与系统临时目录**，用户级记忆根 `~/.acode/memory/` 一律被拒——这意味着 ch08 设计的"记忆相关时由 Agent 自行读取对应文件"对用户级记忆**从未真正可用**。修法：索引段的分节标题带上该层记忆根路径；沙箱构造接受一组额外允许根（由装配处传入记忆根）；行为段补一句"用户要求记住某事时，写入对应记忆文件并同步索引"。 |
| 状态栏 Token 口径 | **上下文占用**（用户已确认）：显示"当前上下文估算 / 上限 / 占比"，与压缩触发口径同源，能直接解释"为何提示无需压缩"；不做会话累计消耗统计（现有单轮用量只在执行器局部，建立会话级累计属另一件事）。 |
| 执行模式的行为 | **有则执行、无则仅切换**（用户已确认）：上一轮规划模式交付过计划，则退出规划模式后把该计划作为任务交给 Agent 执行；没有交付过则只切模式并如实告知。 |
| 计划如何被找到 | 计划正文由 Agent 在规划模式交付时落盘（既有机制），执行入口需要能拿到**该次交付的落盘位置**。取"会话内最近一次规划交付"的落盘位置，**不扫描计划目录取最新文件**——后者会把上一次会话甚至上一个任务的计划当成"本次要执行的计划"。重启后无内存记录，走"无计划"分支。 |
| 参数不合法的处理 | 命令名之后的参数无法解释时（格式不对、可取值非法），由**该命令自己**输出用法提示——框架不做语义判断，只负责把参数原文交下去。框架**不设"参数是否必需"**这个概念：本章没有"不带参数就没法用"的命令，无参数一律有确定含义（查看）。 |
| 权限规则效果 | **扩展为三态，询问与拒绝同级跨层穿透**（用户已确认）：现有规则引擎的效果只有放行与拒绝两种，本次为规则补上"询问"——命中询问规则时不直接判定，而是穿透到人工确认环节（语义是"这条规则要求问你一声"）。跨层按 **deny > ask > allow** 三级判定：任一层 deny → 拒绝；否则任一层 ask → 询问；否则 local > project > user 取第一个非 null。**放行与拒绝之间的既有相对关系不变**，但询问不再受"本地优先"约束——用户级写的一条 ask 不会被项目级更宽的 allow 静默吞掉。这是一次**权限系统语义扩展**，要动效果枚举、求值返回契约、决策链的规则层处理、规则文件的解析与回写四处，属本章的额外工作量。 |
| 询问与既有「始终允许」的先后 | **决策链命中规则层的询问时不立即返回，先让第 ⑦ 层「会话级始终允许」过一遍**（用户已确认）。理由：现实现是规则层命中就 `return`（`PermissionChecker.java:129-137`），若询问也照此立即返回，第 ⑦ 层永远轮不到——而「始终允许」写回的两条路（会话集合与本地规则文件）在新语义下都盖不住一条 ask（ask 跨层穿透），用户选了「始终允许」还会被反复追问。定为：规则层命中询问 → 落到第 ⑦ 层，命中则放行；未命中则返回询问、**不再走第 ⑧ 层模式矩阵**（模式矩阵更宽的放行不得盖掉规则层的询问，与跨层穿透同一条道理）。这样"询问"与"拒绝"在决策链里的分量一致，唯一区别是询问给「始终允许」留了一道门。 |
| 退出命令的归属 | 纳入框架并**保留为可见命令**（用户已确认）：退出归入本地命令段，出现在帮助与补全中，无别名、不接受参数、不产生输出。原先的方案是标为隐藏、借它给"隐藏"机制找一个真实使用者；改为可见后本章没有内置命令使用该机制，`hidden` 字段仍保留、由注册中心单测覆盖（测试里注册一条隐藏命令），留给下一章 Skill 系统做内部命令。退出路径本身仍统一由框架管理。 |
| 命令执行时机 | 维持现状——主循环空闲态执行。**不支持**在 Agent 流式输出过程中输入命令（见 Out of Scope）。 |
| 帮助文本来源 | 由注册中心元数据**生成**，不再手写固定字符串；既有的手写帮助文本随迁移删除。 |
| 版本号来源 | **现有版本串只嵌在启动横幅的 ASCII 文本里**（`ConversationController.java:107` 的 `ACode v0.1.0`），**并没有独立常量**。本章把它抽成一个版本常量，横幅与 `/status` 共用它——不算新增版本机制，只是把已有的串从多行文本里提炼出来，免得靠截取这段艺术字取版本。装配处把该常量作为字符串放进上下文，命令层不直接依赖横幅。 |
| 旧路由类的去向 | 现有路由类（枚举式分类）与主循环里的命令分支**整体删除**，由调度器取代；其配套测试改写为新框架的测试，不留兼容层。 |

## Out of Scope（本阶段明确不做）

- **权限规则的命令入口**（新增 / 修改 / 删除某条规则、重置本地规则）——规则文件由用户直接编辑；`/permission` 只负责查看与切档
- **内置编辑器**（在 TUI 里直接编辑指令文件或记忆文件）——`/memory` 只负责给出路径与内容，实际修改交给用户自己的编辑器。内置编辑器要处理终端挂起/恢复与活跃区渲染的交互，收益不抵风险（同 Tab 补全那类未知项）
- **长期记忆的命令族**（`add` / `del` / `clear`、选作用域的写入菜单）——增改删走对话由 Agent 完成；命令层只保留"查看"与"立即提取"
- **用户自定义命令**（配置文件里写命令、脚本型命令）——留给 Skill 系统
- **Agent 运行期间的命令输入**（流式输出中敲命令）——主循环仍是"读一行 → 执行完 → 再读一行"的串行结构
- **命令级权限控制**（某些命令需确认才能执行）——本章**没有任何命令需要执行前确认**（原先唯一需要确认的"清空记忆"已随记忆入口重定义一起取消：长期记忆不做命令族）。将来若某条命令需要确认，复用既有确认弹窗，不为此建立通用机制
- **命令参数值的补全**（补全会话标识、记忆类别、权限模式等）——只补全命令名
- **命令执行历史、撤销、宏**（把多个命令串起来执行）
- **国际化 / 多语言帮助文本**
- **命令的独立配置项**（每条命令可通过配置改行为）
- **会话累计 Token 统计**（状态栏只显示上下文占用）
- **对既有命令语义的重构**——除上表明确定义的六处形态变化、以及 `/compact` 新增的"低于阈值不压缩"判断外，各命令行为保持原样
