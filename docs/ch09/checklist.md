## 默认值说明（实现与测试必须与此一致）

**命令定义**

- 别名表（**只有这四条有别名**，其余命令无别名）：
  - `help` → `h`、`?`
  - `compact` → `c`
  - `plan` → `p`
  - `status` → `s`
- 名称匹配：**大小写不敏感**（统一转小写后查找）；别名与正式名完全等价
- 参数切分：按**第一个空白字符**切分；其后所有内容（含内部空白与换行）为参数原文，**不做引号解析、不做多参数结构化**
- 命令名后只有空白 → 视为无参数
- 退出命令：`quit`——**可见**，出现在帮助与补全中；无别名、不接受参数、不产生任何输出。**本章没有隐藏的内置命令**；"可标记为不展示"这一机制由注册中心单测覆盖（测试里注册一条隐藏命令，验证它不进帮助与补全、但仍可调用）

**命令形态总则**

- **无参数 = 查看，带参数 = 操作**（主要适用于 `/permission`）
- 无参形态是**弹菜单**的命令（`/resume`、`/memory`），菜单本身就是查看，同样不引入子命令
- 全章只有**一个保留词**：`/memory run`（立即提取一次长期记忆）
- 保留词的判定**优先于**其他解释，大小写不敏感

**参数判定规则**

`/permission <参数>`：参数必须是**四档模式之一**（`default` / `acceptEdits` / `plan` / `bypassPermissions`，**大小写敏感**，沿用既有口径）→ 切换权限模式；否则 → 输出该命令的参数提示语。**没有保留词、不接受其他参数**——规则只读，任何参数都不会写入规则文件。

`/memory <参数>`：只认保留词 `run`，其余一律按参数提示处理——**`/memory` 不接受内容参数**（长期记忆不做命令族）

**命令类型与通道**

| 类型 | 命令 | 结果去向 | 是否发对话请求 |
|---|---|---|---|
| 本地 | `help` `compact` `resume` `memory` `permission` `status` `quit` | 系统消息进输出区（`quit` 不产生输出） | **否**。两个例外只发专用请求、不走对话通道：`/compact` 发摘要请求、`/memory run` 发提取请求 |
| 本地界面 | `clear` `plan` `do` | 系统消息 + 界面/交互状态变化 | `clear` 否；`plan` 带参数时发对话请求、不带参数不发；`do` 有计划时发对话请求、无计划不发 |
| 提示词 | `review` | **不发本地结果**，构造提示词走对话通道 | 是 |

**错误与引导文案**

- 未知命令：`未知命令：/xxx（输入 /help 查看可用命令）`（回显用户实际输入的命令名）
- 裸斜杠（仅一个 `/`）：输出与 `/help` 完全一致
- 命令处理函数抛异常：`命令执行失败：<原因>`，主循环继续
- 参数不合法或不足时展示**该命令自己的参数提示语**（不是通用错误）：
  - `/permission` 参数不是合法模式 → `用法：/permission <模式>（default/acceptEdits/plan/bypassPermissions）`
  - `/memory` 带非 `run` 参数 → `用法：/memory（弹出指令文件菜单）｜ /memory run（立即提取长期记忆）`
  - `/resume` 带任意参数 → `用法：/resume（弹出会话选择菜单，不接受参数）`
- `/help <不存在的命令>` → 指出未找到 + 指向帮助
- 注册期冲突（重名 / 别名被占 / 别名撞正式名）：注册失败并报出**冲突的名字**与**已占用它的命令名**

**`/help` 输出**

```
可用命令：
  /help, /h, /?    显示帮助信息
  /compact, /c     压缩上下文
  /resume          恢复历史会话
  /memory          查看/创建指令文件；run 提取记忆
  /permission      查看权限规则；带参数切换模式
  /status, /s      显示状态信息
  /quit            退出程序

  /clear           清除对话历史
  /plan, /p        切换到 Plan 模式
  /do              切换到执行模式

  /review          审查代码变更

输入 /help <命令名> 查看详细用法。
```

- **按命令类型分三段**（本地 / 本地界面 / 提示词），段间空一行；段内**按注册顺序**排列
- 名称列左对齐、描述列对齐到同一列
- 条数与描述**由注册中心元数据生成**，与实现同源；隐藏命令不进帮助（本章没有隐藏的内置命令，故帮助里就是全部内置命令）
- `/help <命令名>` 输出：描述、用法示例、参数说明、别名；无别名时不显示别名行
- `/help permission` 的参数说明须写明"只接受四档模式之一"，并说明规则只读

**`/status` 输出**

```
ACode 状态
─────────────
模式：default
Token：45,230 / 200,000（23%）
工具：6 个已启用
记忆：user 3 条 · feedback 1 条 · project 5 条 · reference 2 条
工作目录：/home/user/project
版本：v0.1.0
```

- `模式` = 当前权限模式（`default` / `acceptEdits` / `plan` / `bypassPermissions`）
- `Token` = **上下文占用估算 / 上限（占比取整）**，与压缩触发口径同源；千位加逗号分隔
- `工具` = 已启用工具数（不是注册总数）
- `记忆` = 四类记忆各自条数（项目级与用户级合并计数，顺序固定为 user / feedback / project / reference）
- `版本` = 现有横幅里的版本常量（`v0.1.0`），不新增版本机制

**`/compact` 阈值**

- 上下文占用 **< `5_000`** token 时**不发起压缩**，直接输出 `（当前上下文约 N token，无需压缩）`
- ≥ 阈值时走既有手动压缩路径；压缩无变化时沿用既有 `（没有需要压缩的内容）`
- 带参数时参数作为"需要保留的重点"并入摘要提示；**不带参数时摘要提示与改动前逐字相同**（无回归）

**`/resume`**

- 只有一个形态：**弹出交互式选择菜单**（列出历史会话、↑/↓ 选择、回车加载、Esc 取消）；取消 → `（已取消）`
- **不接受任何参数**，不做子命令；带参数时输出 `用法：/resume（弹出会话选择菜单，不接受参数）`
- 没有可恢复的会话时 → `（没有可恢复的会话）`（沿用既有文案）
- 保留为可见命令：出现在帮助列表与 Tab 补全候选中
- **不产生对话模型请求**（唯一例外：加载的会话上下文已超自动压缩触发点时，沿用既有恢复联动压缩一次）

**`/memory`**

- 无参数：**弹出菜单**（↑/↓ 选择、回车确认、Esc 取消），列出三层指令文件，末尾附一项"查看长期记忆"：

  ```
  （↑/↓ 选择，回车确认，Esc 取消）
    项目指令   <项目根>/ACODE.md              已存在 12 行
    本地指令   <项目根>/.acode/ACODE.md       未创建
    用户指令   ~/.acode/ACODE.md              已存在 5 行
  ──────────────────────────────────────
    查看长期记忆（6 条）
  ```

- 选中某一层指令文件：
  - 已存在 → 输出路径、行数与**完整内容**（进回滚，可滚动查看）
  - 不存在 → **创建空文件**，输出路径与一行提示（用编辑器写入；指令文件的改动下个会话生效）
- 选中"查看长期记忆" → 列出长期记忆条目（类别、名称、描述，按类别分组、**项目级在前**）；无记忆时 `（暂无记忆）`
- 菜单取消（Esc）→ `（已取消）`，**无文件被创建或修改**
- 带保留词 `run` → 立即触发一次长期记忆提取，输出沿用现有文案：`记忆提取完成：新增 X · 更新 Y · 删除 Z` / `（没有值得记忆的内容）` / `记忆提取失败（未写入任何文件）`
- 带其他参数 → 输出该命令的参数提示语
- **不产生对话模型请求**（`run` 触发的是独立提取调用，不走对话通道）

**长期记忆的维护方式（没有命令入口）**

- 长期记忆的**增 / 改 / 删全部经对话由 Agent 用文件工具完成**——命令层不提供 `add` / `del` / `clear`
- 因此 Agent 必须能到达记忆文件，三件事一起成立才有效：
  - 注入的索引段里，每节标题**带该层记忆根路径**（`## Project` → `<项目根>/.acode/memory/`；`## User` → `~/.acode/memory/`）
  - 路径沙箱**放行两级记忆根**（用户级在项目外，作为额外允许根传入）
  - 行为段含约定：用户要求记住某事时，写入对应记忆文件并同步索引
- 沙箱放行范围**只增加记忆根**：项目外、记忆根之外的用户目录路径**仍被拒绝**

**`/permission`**（只读查看 + 切档）

- 无参数：**列举**三层规则的完整状态——

  ```
  当前权限模式：default
  用户级    ~/.acode/permissions.yaml               1 条
    Bash(git push *) → deny
  项目级    <项目根>/.acode/permissions.yaml         0 条
  项目本地  <项目根>/.acode/permissions.local.yaml   2 条
    ReadFile(*) → allow
    Bash(npm *) → ask
  ```

  每层都显示**文件路径**（用户据此去编辑）、条数与规则摘要（工具名 + 规则模式 + 效果）；某层无规则时只显示 `0 条`
- 带参数：参数必须是四档模式之一 → 切换，输出 `（已切换到权限模式：<模式>）`（沿用既有文案）；否则输出用法提示、模式不变
- **规则只读**：`/permission` 不接受任何会写入规则文件的参数——规则的增 / 改 / 删都由用户直接编辑上面列出的三个文件
- 切档「只改内存、不写回 `config.yaml`」的既有语义保持不变
- **不产生模型请求**
- **`ask` 的语义**：命中询问规则时**不判定**，穿透到既有的人工确认环节（三选一）。跨层按 **deny > ask > allow** 三级判定——某一层为 deny 时，另一层的 ask 不能把它翻成询问；某一层为 ask 时，另一层更宽的 allow **不能把它盖掉**（询问跨层穿透）。同层内 ask 与 allow 一样遵循「后匹配者覆盖先匹配者」
- **询问与「始终允许」的先后**：规则层命中询问时**不就地返回**，先让第 ⑦ 层「会话级始终允许」过一遍——命中则放行（用户已经明确说过始终允许），未命中才落到人工确认，并**不再往下走模式矩阵**（模式矩阵更宽的放行不得盖掉规则层的询问，与跨层穿透同一条道理）。验收口径：某工具命中 ask 规则后，用户在三选一里选「始终允许」，同一工具下次调用**不再询问**

**权限规则效果（三态）**

- 效果枚举：`allow` / `deny` / `ask`（规则文件里的字符串即这三个词）
- 跨层判定为 **deny > ask > allow** 三级：任一层 deny → 整体拒绝；否则任一层 ask → 询问；否则 local > project > user 取第一个非 null
- 规则文件里手写的 `effect: ask` 必须能读回生效；非三态之一的字符串仍按坏条目丢弃
- **写入不得损坏已有规则**：本地文件里已有的 ask 规则，在「始终允许」触发的回写后必须仍是 `ask`（不得被改写成 `deny`）

**`/plan` 与 `/do`**

- `/plan` 无参数：切到规划模式，输出 `（已进入规划模式：只读探索，计划落盘到 .acode/plans/）`（沿用既有文案），**不发起模型请求**
- `/plan <任务>`：切到规划模式，并把 `<任务>` 作为用户输入发出
- `/do` 无待执行计划：切回非规划模式，输出 `（已退出规划模式；没有可执行的计划）`，**不发起模型请求**
- `/do` 有待执行计划：切回非规划模式，把**计划正文**作为用户输入发出，输出 `（已退出规划模式，按计划开始执行）`
- "待执行计划" = **本次会话内最近一次规划模式交付**的落盘位置；`/clear` 或加载会话后该状态清空（回到"无计划"分支）

**`/review` 提示词**

- 提示词必须包含的语义：分析当前工作区的**未提交变更**、按问题/风险/建议组织、指明**具体文件与位置**、**只审查不修改**
- 带参数时：提示词中含 `额外关注：<参数>`
- 命令本身**不产生本地输出**（不往系统消息通道写审查内容）

**命令执行时机**

- 命令在主循环空闲态执行；不支持 Agent 流式输出期间输入命令

**Tab 补全**

- 仅 `/` + Tab → 候选 = 全部**可见**命令，**含 `/quit`**（隐藏项不进候选；本章没有隐藏的内置命令）
- `/前缀` + Tab → 候选 = 名称以该前缀开头的可见命令；前缀大小写不敏感
- 候选唯一 → 直接补全进输入框（不提交）
- 候选多个 → 以列表呈现，每条含**命令名与描述**
- 候选 0 个 → 无操作（不报错、不清空输入）
- 候选顺序与帮助列表一致（即注册顺序）
- 补全不得污染原生回滚区（滚动上去无残影）
- 具体交互形态（内建自绘 vs 自定义下拉）以 T2 真机验证结论为准，结论记于 `spec.md`

## T4 权限规则三态与只读列举

- [ ] 规则清单反映三层规则的**实际文件内容**：每层带文件路径、条数与规则摘要（工具名 + 规则模式 + 效果）
- [ ] 手写 `allow` / `deny` / `ask` 三种效果的规则后，`evaluate` 分别返回放行 / 拒绝 / 询问
- [ ] 命中 `ask` 规则时决策链的规则层返回**询问态**（既不是放行也不是拒绝）
- [ ] 跨层：任一层 deny 不被其他层的 ask 翻转；任一层 ask **不被其他层更宽的 allow 盖掉**（穿透生效）；三层皆无结果才落到决策链下一层
- [ ] 命中 ask 规则后选「始终允许」→ 同一工具**下次调用直接放行、不再询问**（询问不就地返回，第 ⑦ 层有机会命中）
- [ ] 在本来会放行的权限模式下（如 `bypassPermissions`），规则层的 ask **仍返回询问态**（模式矩阵不吞询问）
- [ ] 「始终允许」写回本地文件后，文件里原有的 ask 规则**仍然是 `ask`**（未被改写成 `deny`）
- [ ] 手工在规则文件里写一条 `effect: ask` → 能读回并生效（**不被当坏条目静默丢弃**）
- [ ] 规则文件里的效果字符串写错（非三态之一）或格式不合法（缺括号、空工具名）→ 该条目被丢弃、其余条目照常生效
