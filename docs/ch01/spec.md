# ACode 阶段一：交互式对话 — spec

> 最后更新：2026-08-07

## 背景

ACode 是一个终端 AI 编程助手（Coding Agent），对标 Claude Code，使用 Java 开发。这是一个从零开始的长期项目，后续阶段会逐步加入 tool use、文件操作、代码编辑等 Agent 能力。

本阶段（阶段一）的目标是打好地基：用户在终端启动 ACode 后，进入一个全屏交互式对话界面，向大模型提问，AI 的回复流式地逐字显示。支持多轮对话（AI 记住会话内说过的话）、会话保存与恢复、两家大模型后端（Anthropic Claude、OpenAI）的配置切换。

## 目标用户

- 本人：日常在 Windows 终端里向 AI 提问、写代码、查资料，替代打开浏览器使用网页版
- 后续阶段的潜在使用者：终端开发者

## 能力清单

1. 终端启动后进入全屏对话界面：上方为输出区（可滚动），下方为输入区
2. 支持多行输入（Shift+Enter 换行），可粘贴大段代码不丢内容
3. 输入区支持行编辑（光标移动、退格、历史记录上下翻）
4. AI 回复流式显示（SSE 边生成边打印，不等完整结果）
5. 回复按 Markdown 子集做简单 ANSI 着色（代码块、加粗、标题、行内代码）
6. 多轮对话：每轮自动携带全部历史消息
7. 会话可保存到本地、下次启动可恢复继续
8. 支持 Anthropic Claude 与 OpenAI 两家后端，通过 YAML 配置切换
9. 配置支持全局（~/.acode/config.yaml）与项目级（.acode/config.yaml）两级，项目级优先
10. 支持 Claude extended thinking（思考内容不展示，仅提升回答质量）
11. 对话历史超出模型上下文窗口时自动丢弃最早的消息
12. API 429 限流与 5xx 服务端错误自动重试，其他错误给出可读提示
13. 斜杠命令：/quit、/clear、/help
14. 生成过程中 Ctrl+C 中断当前回复，可继续输入新问题

## 非功能要求

- 首 token 延迟：网络正常时，回车后 3 秒内开始输出
- 生成过程中输入框不被阻塞，可随时中断、继续输入
- 界面不闪烁、不重影（增量渲染）
- 配置错误、认证失败、网络错误均显示可读的中文提示，并指出问题来源（全局还是项目级配置）
- 核心层（Provider、SSE 解析、配置加载、上下文截断）有单元测试，不依赖真实网络

## 设计骨架

### 分层结构

```
┌─────────────────────────────────────┐
│  UI 层：全屏终端界面                 │
│  输出区（滚动、着色）/ 输入区（多行）│
│  斜杠命令路由 / 流式打印             │
├─────────────────────────────────────┤
│  对话编排层                          │
│  消息列表 / 上下文截断 / 会话生命周期│
├─────────────────────────────────────┤
│  Provider 抽象层                     │
│  统一接口 + Anthropic/OpenAI 实现    │
│  重试策略 / 错误分类                 │
├─────────────────────────────────────┤
│  传输与配置层                        │
│  SSE 解析 / YAML 配置加载与合并      │
└─────────────────────────────────────┘
```

- **UI 层**：基于终端全屏渲染。输入区用行编辑能力较强的终端库（JLine 系列）；输出区自绘滚动区，流式增量着色。UI 层只依赖「事件」与「文本流」，不感知具体后端。
- **对话编排层**：持有消息列表，负责组装每次请求、按窗口估算丢弃旧消息、触发会话保存。不感知界面细节。
- **Provider 抽象层**：统一接口提供「流式对话」能力，通过回调把增量文本逐段交回给上层；错误被分类（认证失败 / 限流 / 网络 / 服务端 / 参数错误），上层据此决定重试或提示。
- **传输与配置层**：SSE 解析器把原始字节流转成结构事件；配置加载按「项目级覆盖全局」的规则合并，缺失或非法字段给出具体报错。

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 界面形态 | 全屏 TUI（上方输出、下方输入） |
| 会话记忆 | 会话内多轮 + 本地保存可恢复 |
| thinking | 始终开启，不展示思考内容 |
| 上下文超限 | 自动丢弃最早消息 |
| OpenAI 端 | 仅普通 chat，不支持 reasoning 模型 |
| 配置覆盖 | 全局为默认，项目级覆盖 |
| 输出展示 | Markdown 简单着色 |
| 斜杠命令 | /quit /clear /help |
| 重试 | 429/5xx 自动重试，其他错误直接提示 |
| 技术栈 | Java 21 + Maven + JLine + Jackson + SnakeYAML |

### 配置模型

四个核心字段：`protocol`（选哪家协议）、`model`、`base_url`、`api_key`。另有上下文窗口上限（用于超限丢弃）。项目级配置可只覆盖其中某几个字段（如只换 model 或 api_key）。

### 会话文件

会话以 JSON 保存在用户主目录的 ACode 数据目录下，内容为消息历史；`--resume` 启动参数恢复最近一次会话。

## Out of Scope（本阶段明确不做）

- Tool use、文件操作、代码编辑、Agent 循环（后续阶段）
- OpenAI reasoning 模型（o 系列）
- 多 provider 同时激活、运行中切换 provider
- 对话历史摘要压缩（替代「丢弃」的更优策略，后续再评估）
- 完整 Markdown 渲染（表格、图片、嵌套列表、LaTeX）
- 会话列表的界面化管理（切换/删除历史会话）
- HTTP 代理、自定义 CA 证书、自签名 TLS
- token 精确计数（按字符估算，误差接受）
- 配置加密存储、多账号管理
