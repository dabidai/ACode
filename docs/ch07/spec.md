# ACode 阶段七：上下文管理 — spec

> 最后更新：2026-09-03
> 功能诉求见 `prompt.md`；参考素材见 `design-notes.md`（FlashMemory KV Cache 论文摘记 + agent-docs 第8章 ch8-1「理论学习：上下文压缩与 Token 管理」）
> 本文只定"做什么/为什么"，不含函数名、参数名、默认值与错误文本；具体阈值与文案集中在 `checklist.md` 顶部

## 背景

ACode 目前无法支撑 Agent 长时间工作：

- 对话历史随轮次线性增长，模型无状态、每轮把完整历史重发；撞上上下文窗口上限时 API 直接报错、Agent 瘫掉。
- 超过窗口上限时，现在只是从最旧消息开始静默裁剪（Recency-Only）：远距的关键决策被悄悄丢掉，模型不知情、也无法找回。
- 每个工具结果在进对话前都被截断到很短的固定长度，超长尾部**静默丢失**，且历史里不给模型任何可自取的路径——读一个大文件的输出，模型只能看到开头一小段。

本阶段给 ACode 装上**上下文管理**能力：让 Agent 能在有限的 Token 预算内长时间工作。核心是一条"能轻则轻"的分层策略——先拿近乎零成本的大结果落盘挡掉单次超大输出，再在对话逼近上限时用结构化摘要兜底，最后用"撞墙自动压缩一次"防止估算偏差把 Agent 打死。用户说的话尽量原文保留，替换类操作保持历史前缀稳定以利 prompt cache 持续命中。本阶段同时**移除现状"从最旧消息静默裁剪"的兜底（Recency-Only）**：由自动压缩的前置守卫保证每次请求都能发出，残余超窗仅剩"单条消息自身超窗"这一可见错误情形。

## 目标用户

- 本人：跑重构、批量改文件这类多轮长任务，希望 Agent 从十几轮就撞墙变成能干完全程。
- 后续潜在使用者：命令行工作流的开发者，在有限上下文预算里让 Agent 长时间干活。

## 能力清单

1. **Token 预算估算**：复用现有近似口径（不追求精确 tokenizer），对"当前请求将携带的内容"整体估算，支撑压缩触发判断与压缩前后的对比展示。
2. **大结果落盘**：单个工具执行结果超过保留上限时，全文幂等写入当前工作目录下本地文件，对话历史里只保留定长预览 + 可读路径；信息不再丢失，模型需要时可随时读回全文。
3. **同批聚合限额**：同一轮多个工具结果合并总量超限时，从体积最大者开始落盘替换，直到该批合计回落到预算内。
4. **决策冻结**：每个工具结果"是否落盘替换"只决策一次、整会话冻结；已被替换的此后每轮原样重放同一段预览串。保证历史前缀逐字节稳定，prompt cache（已启用）持续命中。
5. **结构化摘要（Auto-Compact）**：每轮开始检查预算；逼近窗口上限时，用一次**不携带任何工具**的模型调用，把旧消息压成一份多段结构化摘要并原地替换。自动触发只在「存在早于保留尾的可压缩完整轮次（非空摘要区）且压后能落到触发点以下」时执行——避免"压了也压不低"时每轮空跑一次摘要调用。
6. **摘要内容纪律**：指令明确要求——用户说过的话尽量原文保留、当前工作写最详细、待办与下一步显式列出；生成采取"先起草、后成文、草稿丢弃"的两阶段方式提升质量。“用户消息原文保留”是**优先级指引而非硬性逐字全量**：摘要空间不足（如整份粘贴文件）时由摘要模型自行取舍为要点，不设系统级逐字预算/截断阈值/截断标记；重建的通用边界提醒（见 #7）防模型凭要点脑补细节。
7. **摘要后重建**：压缩成功后把对话原地重建为「摘要消息(user) → 边界提醒(assistant，独立一条) → 保留尾（预算内近期完整轮次）」；planner 不写死首条角色，只保证不变量：整段角色相邻合法、请求以 user 结尾、无悬空 tool_use/tool_result、重建后整体估算（与触发同一口径）≤ 自动压缩触发点。**不可压缩（逐字保留）仅限未闭环步**——最新一条未答复 user 原文 + 最末尚无结果的 assistant tool_use；**已闭环轮次**（结果已回填、流程已推进）一律属普通历史，交给保留尾预算或摘要区，因此单个长请求内连续多轮也可中途压缩。边界提醒明确告知模型"具体内容请重新读取，勿凭摘要猜细节"。
8. **熔断**：摘要生成连续失败达到阈值后，本会话停止自动触发、改由用户手动处理，避免"超限→触发→失败→重试"死循环；摘要请求自身过长时按"丢弃最旧分组再试"降级。熔断的作用域只罩**每轮开始的自动触发**——紧急压缩（见 #9）与手动 /compact 是独立的保命/用户路径，不受自动熔断约束，否则一次估算偏差会把保命网和自动触发一起禁掉。**任何一次成功的压缩都会复位连续失败计数**：成功即证明"这份历史当前可压缩"，连续失败前提随之打破，熔断不会把会话永久锁死在"永不自动压缩"——手动压成功后自动路径自行恢复。
9. **紧急压缩**：正常请求被"上下文超长"类错误拒绝时，就地压缩一次再用新历史重试原请求，避免一次估算偏差就把 Agent 打死。
10. **手动 /compact**：空闲时同步执行一次压缩，与自动压缩同样重建为「摘要 + 边界提醒 + 保留近期完整轮次」，展示压缩前后预算变化；仅当历史小到没有可压缩的摘要区时提示无需压缩；用于预防性压缩与话题切换。
11. **状态一致性**：会话清空、加载/恢复历史等清空点联动重置冻结与熔断状态；压缩后的历史随既有会话机制正常存档与恢复。

## 非功能要求

- **零新增依赖**：复用现有 provider 流式通道、消息模型与估算；不引入 tokenizer 库、新模型后端或第三方摘要服务。
- **摘要调用不带工具**：摘要生成请求不携带工具定义，模型"看不到工具"从而不会误调；其余正常请求的工具列表不受影响。
- **失败不破坏历史**：摘要成功后才重建历史；任何失败保持原历史不变，Agent 可继续。
- **磁盘副作用受限**：落盘文件只写当前工作目录下、进程沙箱允许的范围（沿用 `.acode` 命名空间），模型可用既有读文件工具自取；不写全局路径。
- **并发与一致性**：沿用既有代次(epoch)同步语义；重建是原子的，被取消的旧循环线程迟到写入仍被忽略。
- **估算不精确可容忍**：一次漏判由紧急压缩兜底，不让 Agent 因估算误差整体瘫掉。
- **可测试**：阈值、决策、重建、熔断、触发均可用假 Provider + 临时目录在单测/集成层面可观测，不依赖真实模型与网络。

## 设计骨架

### 分层结构

```
┌──────────────────────────────────────────────────────────────┐
│  装配层（每会话一次）                                           │
│  ContextManager：策略常量 + 落盘存储 + 冻结状态 + 摘要执行器     │
│  → 注入 Agent（自动触发/紧急压缩/大结果落盘）与手动命令两处       │
├──────────────────────────────────────────────────────────────┤
│  策略与状态                                                    │
│  预算策略（固定常量，非百分比）   替换决策/冻结状态（按 id 记账） │
├──────────────────────────────────────────────────────────────┤
│  第一层 大结果落盘：判断 → 幂等写盘 → 生成定长预览（含路径）      │
│  第二层 结构化摘要：摘要指令 → 生成（先起草后成文）→ 熔断/降级    │
├──────────────────────────────────────────────────────────────┤
│  对话重建：摘要消息 + 边界提醒 + 保留近期完整轮次（原子替换）     │
├──────────────────────────────────────────────────────────────┤
│  底层复用：现有 Conversation 历史/估算/清洗 · 现有 provider 流式 │
└──────────────────────────────────────────────────────────────┘
```

### 大结果路径（Layer-1，预防）

```
工具结果产生（同批多个）
  → 对"新出现"的结果逐个评估：超过保留上限 → 全文幂等落盘
  → 同批合计超聚合限额 → 从最大者补落盘到回落到预算
  → 历史只记「定长预览 + 文件路径」；≤上限者全文保留
  → 每个结果只决策一次并冻结；已被替换的此后原样重放同一预览
```

### 长对话路径（Layer-2，治疗）

```
每轮开始 → 估算当前历史（含系统提示与环境快照）
  → 逼近窗口上限 → 触发结构化摘要（不携带工具）
      ├─ 摘要请求自身过长 → 丢最旧分组重试降级
      ├─ 连续失败达阈值 → 熔断，交用户手动 /compact
      └─ 成功 → 原地重建「摘要 + 边界提醒 + 保留近期轮次」→ 继续本轮
正常请求被"上下文超长"拒绝 → 紧急压缩一次 → 重试原请求一次
仍有超窗（仅剩"单条消息自身超窗"不可压）→ 可见错误、不改历史，交用户处理
（不设"从最旧裁剪"静默兜底：自动/紧急压缩后整体估算必 ≤ 触发点）
```

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 大结果可见上限 | 采用理论学习口径：普通量级结果全文保留进历史，超过明确上限才落盘替换（上限数值见 checklist）。该上限与现行"一律截短"不同——短结果不再被砍 |
| 聚合限额作用域 | 只对**同批新产生**的结果约束，不做历史回溯式替换——历史一旦写入不再改动，天然满足前缀稳定（决策冻结的简化落地） |
| 触发用固定余量 | 摘要输出预留 + 安全余量均为固定常量、不随窗口比例浮动：保护的是"单轮波动"，与窗口大小无关；不同窗口下触发点随之平移 |
| 摘要调用形态 | 不携带工具、thinking 关闭；指令走两阶段（草稿丢弃）；用户消息原文优先保留；请求级 max_tokens 独立给足（防超长摘要被截断，数值见 checklist），摘要请求直接经 `ChatRequest.builder` 构造、不经 `Conversation.buildRequest`（避免被裁剪/注入轮次级提醒） |
| 用户消息处理 | "原文优先"是**优先级指引而非硬性逐字全量**：不设系统级逐字预算/截断阈值/截断标记，空间不足由摘要模型自行取舍（对齐 ch8-1）；重建的通用边界提醒防凭摘要脑补 |
| 压缩后处理 | 旧对话**原地替换**为摘要；恢复只做"边界提醒"，不额外重注入最近读过的文件（ACode 不追踪最近读文件，改动最小） |
| 熔断作用域 | 只罩每轮开始的自动触发（能力 #8）；紧急压缩（#9）与手动 /compact 是独立的保命/用户路径，不受自动熔断约束，避免估算偏差把保命网一起禁掉 |
| 熔断复位 | 任何成功的压缩（含手动 /compact）清零连续失败计数、解除跳闸——成功证明"这份历史当前可压缩"；清空/加载/恢复等历史重置点按 #11 联动复位，计数属运行期控制状态、不随会话序列化 |
| 自动触发守卫 | 自动压缩仅在「非空摘要区（早于保留尾的完整轮次）且压后整体估算 < 触发点」时执行，否则本轮跳过、不调用模型——超大进行中内容不会造成"成功但压不低"时每轮空跑摘要；熔断只统计真正的失败（守卫后的触发都是有望压低的） |
| 手动命令 | 空闲态同步执行，阻塞主循环直至完成/失败，输出前后预算与结果 |
| 超窗残余（删除"最旧裁剪"兜底） | 自动/紧急压缩后整体估算必 ≤ 触发点——不可压缩仅未闭环步 + 保留尾，量级有界（Layer-1 把单轮结果限在单条上限内）；仅当**单条消息自身超窗**（如用户一次粘贴超窗长文）才可能仍超窗 → 走可见错误、不改历史，交用户拆小或用文件读取；绝不静默裁剪、绝不因压缩引入悬空工具块或非相邻角色 |
| 状态清理 | 会话清空/加载/恢复等历史重置点同步重置冻结与熔断状态；落盘文件不删（见 Out of Scope） |
| 重建形态与保留/进行中轮 | 重建为「摘要(user) → 边界提醒(assistant，独立一条) → 保留尾」；planner 不写死首条角色，只守不变量：整段角色相邻合法、请求以 user 结尾、无悬空 tool_use/tool_result、重建后整体估算 ≤ 触发点。**不可压缩（逐字保留）仅限未闭环步**：最新一条未答复 user 原文 + 最末尚无结果的 assistant tool_use（结果已回填则整对保留）——压缩不得把正要回答的问题或正在执行的工具结果压进摘要。**已闭环轮次**（结果已回填、流程已推进）一律属普通历史，可进保留尾预算或摘要区——单请求内连续多轮的长任务可中途压缩，不会因"整段任务受保护"而压不动 |

## Out of Scope（本阶段明确不做）

- 精确 tokenizer / 按 token 的逐字节计量；估算误差由紧急压缩兜底
- 落盘文件的生命周期管理（GC/清理/跨会话复用校验）；压缩后摘要依赖的文件重读由模型自己决定
- 摘要后恢复"最近读过的文件内容"/技能定义重注入（仅边界提醒）
- 压缩策略的启发式调参或机器学习优化
- 把工具 schema / system 提示做进预算的精确计量（预算估算覆盖历史 + 系统提示 + 环境快照，工具定义与正常请求的边际开销由"提前触发的固定预留"覆盖）
- 不同模型后端的 prompt cache 语义特化（决策冻结对任一后端无副作用，仅对支持缓存的通路有收益）
