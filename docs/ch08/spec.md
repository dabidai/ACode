# ACode 阶段八：记忆系统 — spec

> 最后更新：2026-09-10
> 功能诉求见 `prompt.md`；本文只定"做什么/为什么"，不含函数名、参数名、默认值与错误文本；具体阈值与文案集中在 `checklist.md` 顶部
> 已确认的四个前置决策：会话存储**直接替换**（不兼容旧 JSON 格式）；记忆索引**会话启动注入一次、会话内不刷新**；自动提取**默认开启 + 配置可关**；过期会话**只标记不删**

## 背景

ACode 现在只有"一次进程内"的对话，没有任何跨会话存在的东西：

- **会话不按项目隔离、丢了就没了**：会话存成"一会话一个 JSON 文件"、写死在用户主目录的固定位置，且只在**退出时**整存一次。同一台机器上所有项目的会话混在同一个池子里；进程被 Ctrl+C 之外的意外杀掉、断电、崩溃时，本次会话**完全不落盘**。
- **没有项目上下文的载体**：每次启动都要重新交代"这是什么项目、用什么技术栈、代码规范是什么"。`~/.acode/` 下已经有 config/permissions 等命名空间，项目级 `.acode/` 只用了 config/permissions/plans/tool-results，缺"项目指令文件"这一层。
- **对 Agent 的纠正说完就忘**：用户说过的"用互斥锁而不是消息通道""我喜欢简单的风格"，下个会话从头再犯；项目里踩过的坑（某个依赖版本的坑、某张表的语义）也没有地方沉淀。

本阶段给 ACode 补上**记忆系统**——把"跨会话存在"的三类长期记忆做齐：**项目指令文件**（ACODE.md 三层加载 + `@include` 展开）、**会话持久化**（项目级 JSONL、追加写入、可恢复）、**自动记忆**（四类记忆文件 + 索引 + 每轮结束的异步提取）。三者最终汇入同一条**注入管线**，作为会话级 system 提示的一部分。

## 目标用户

- 本人：同时在多个项目间切换，希望每个项目有自己的会话池与项目规范，退出/崩溃后能续上；对 Agent 的纠正能被记住并复用。
- 后续潜在使用者：把 ACode 当日常命令行工作流的开发者，需要"项目级约定写一次、全组长效"与"个人偏好在所有项目生效"两档不同的记忆。

## 能力清单

### 一、项目指令文件（ACODE.md）

1. **三层加载与拼接**：按「项目根/ACODE.md（团队规范）→ 项目根/.acode/ACODE.md（个人本地偏好）→ 用户主目录/~/.acode/ACODE.md（个人跨项目偏好）」顺序加载，文件不存在即跳过；三者**不做覆盖、按内容拼接**，以固定分隔线分隔，高优先级（项目根）排在最前。
2. **`@include` 展开**：指令文件内以固定行格式引用其他文件，被引文件内容在此处原地展开；用于解决单文件臃肿（把大段规范拆成多个文件）。
3. **展开安全边界**：固定深度上限防无限递归；维护"已展开文件集合"防同一文件被重复展开（同时天然打断 A↔B 互相引用的环）；**项目级文件**中写的引用路径若解析后逃逸出项目根 → 拒绝展开；**用户级文件**中的引用路径若逃逸出用户主目录 → 拒绝展开。所有拒绝都是跳过 + 告警一行，不中断启动。
4. **单文件体量上限**：单个被展开文件超过上限时截断并附提示，防止一个巨型日志文件把 system 提示撑爆。
5. **注入位置与稳定性**：展开后的完整文本在**会话启动时构建一次**、作为 system 提示的固定一段注入，会话内字节不变（保住 prompt cache 前缀稳定，与阶段七决策冻结一致）。

### 二、会话持久化（JSONL）

6. **项目级会话池**：会话文件放在当前项目根目录下的 `.acode/sessions/`，与项目绑定；换项目即换会话池，不再全局混放。
7. **JSONL 存储格式**：每行一个 JSON 对象、代表一条消息，字段为「角色、内容、时间戳」；内容既可是纯字符串也可是结构化块数组；时间戳为整型 Unix 秒。追加写入（一行一条），不做整体重写式存储。
8. **读时容错**：逐行解析，**格式非法的行直接跳过**并继续读下一行（含进程被杀留下的半行）；会话文件缺失、为空、全部行非法都按"空会话"处理，不抛错。
9. **活跃会话实例**：会话在内存中是一个活跃对象，持有该会话文件的打开句柄；每追加一条消息**先写文件、再更新内存**；`/quit`、EOF、Ctrl+C 等退出路径关闭句柄。
10. **压缩后整段重写**：上下文压缩会把整段历史原地重建（阶段七），此时"追加"语义不再成立——会话文件按重建后的历史**整段重写**；重写须原子（先写临时文件再原子替换），避免重写中途崩溃把会话文件写坏。
11. **恢复四步**：
    1. 逐行解析，非法行跳过；
    2. **验证消息链完整性**：追踪所有未完成的工具调用，把历史**截断到最后一个「全部工具调用都有结果」的位置**（末尾无结果的丢弃），保证恢复出的历史能直接发请求；
    3. **检查 Token 量**：恢复出的历史若已达自动压缩触发点，走阶段七的压缩路径（恢复长会话不会一上来就撞墙）；
    4. **时间跨度提示**：距上次活跃超过上限时，插入一条提醒消息告知"上次会话是什么时候、中间可能有代码变更、建议重新读取相关文件"，避免 Agent 拿过期文件内容做决策。
12. **会话列表**：直接扫描会话目录即得列表；按最后活跃时间排序、活跃的在前；超过过期阈值仍不活跃的会话**标记为已过期并排在最后**，不自动删除。
13. **续写而非另存**：选择加载某个会话后，后续消息**追加进同一个会话文件**（该会话重新成为活跃会话），不新建文件、不产生分叉副本。

### 三、自动记忆

14. **记忆分类与归属**：四类——用户偏好、纠正反馈（用户级目录）；项目知识、参考信息（项目级目录）。用户级跨项目共享，项目级随项目走。
15. **一记忆一文件 + 索引**：每条记忆一个 Markdown 文件，带结构化头部（名称、描述、类型）与正文（正文含"为什么/怎么用"两行，对齐 feedback/project 的写法）。索引文件 `MEMORY.md` 只存指针，每行一条、指向记忆文件。
16. **索引注入上限**：索引注入 messages 时受行数与体积双重上限；超限则截断并附警告行。索引与 ACODE.md **走同一条加载管线**（同为本阶段能力 #5 的注入位置）。
17. **按需取全文**：只有索引进上下文；某条记忆的详细内容与当前任务相关时，由 Agent 用既有读文件工具自行读取对应记忆文件——不做自动全文注入。
18. **异步提取**：每轮 Agent 循环结束（模型给出最终回复、不再调用工具的那一刻）后，**后台异步**回顾本轮对话，判断有没有值得长期记忆的内容；提取通过一次**独立的模型调用**完成——把索引 + 现有记忆清单 + 最近一轮对话发给模型，让它按四个类别分别决定创建 / 更新 / 删除。
19. **提取纪律**：提示词明确"已有相同含义的记忆不要重复创建""没有值得记忆的内容就什么都不做"；模型输出结构化操作列表，解析失败即本轮**什么都不做**（宁可漏记，不可错写）。
20. **写回安全**：记忆文件的写入路径必须落在对应记忆根目录内，文件名经白名单化处理——模型返回的任何路径穿越写法都被拒绝，不能借记忆写回往任意位置落文件。
21. **并发与代次**：同时最多一个提取任务在跑，与用户下一轮输入互不阻塞；提取结果落盘前校验会话代次，已被 `/clear`、会话加载等操作作废的那一轮结果丢弃不写。
22. **手动入口**：提供命令列出两级记忆与索引状态；并提供"立即同步提取一次"的手动触发，供关掉自动提取后仍能使用该能力。
23. **配置开关**：自动提取由配置项控制，默认开启；关掉后不再有每轮结束的后台模型调用，手动入口仍可用。

### 四、装配、注入与状态一致

24. **注入管线统一**：ACODE.md 展开文本与记忆索引在会话启动时构建一次，作为 system 提示的固定段注入；**会话内不刷新**——异步提取新写入的记忆在下个会话生效，以保前缀字节稳定（prompt cache 持续命中）。
25. **状态一致**：`/clear`、加载/恢复会话等历史重置点同步重置会话追加状态与提取侧状态；恢复后的历史随既有的清除钩子机制联动。

## 非功能要求

- **零新增依赖**：`@include` 展开、JSONL 编解码、记忆读写全部用 JDK 既有能力（`Files` + 既有 Jackson）；不引入向量库、检索库、模板引擎。
- **不做检索**：不引入向量数据库 / RAG / 语义检索；记忆的"找到"靠索引注入 + Agent 主动读文件。
- **启动不因记忆设施失败**：ACODE.md 任一层缺失/畸形/被拒、会话目录不可读、记忆文件头部残缺，都只降级（跳过该来源 + 告警一行），**不阻断启动、不阻断对话**。
- **写入限域**：记忆写回与会话写入只落在 `<项目根>/.acode/`、`~/.acode/` 两个既有命名空间内；不写全局路径、不改用户已有的非 acode 文件（不自动改 `.gitignore`）。
- **不破坏对话**：会话写盘失败（磁盘满/权限）只记告警并继续本轮对话，不因持久化失败让 Agent 卡死或丢消息。
- **异步提取不阻塞主流程**：提取跑在应用级虚拟线程池，失败只记日志、不向用户报错、不影响下一轮对话。
- **前缀稳定**：本阶段所有注入均为"会话启动一次"，会话内 system 提示字节不变；决策冻结（阶段七）与记忆写入互不干扰。
- **可测试**：三层指令文件加载、`@include` 边界、JSONL 编解码与恢复四步、索引上限截断、提取写回与路径拒绝，全部可用 `@TempDir` + 假 Provider 在单测/集成层面观测，不依赖真实模型与网络。

## 设计骨架

### 分层结构

```
┌────────────────────────────────────────────────────────────────┐
│  装配层（每会话一次）                                            │
│  指令与记忆装配：ACODE.md 三层+展开 · 记忆索引 · 注入管线         │
│  会话装配：项目级会话目录 · 活跃会话句柄 · 恢复器                 │
├────────────────────────────────────────────────────────────────┤
│  注入（会话启动一次、会话内不变）                                │
│  system 提示 = 既有七段 + [项目指令段] + [记忆索引段]             │
├────────────────────────────────────────────────────────────────┤
│  会话：JSONL 追加 ← 消息写入 → 内存历史                          │
│        └ 压缩重建 → 整段原子重写                                 │
│        恢复 = 解析跳过 → 链截断 → 预算检查 → 时间跨度提示         │
├────────────────────────────────────────────────────────────────┤
│  记忆：索引加载/截断 · 一记忆一文件 · 每轮结束异步提取（独立调用）│
├────────────────────────────────────────────────────────────────┤
│  底层复用：既有 Conversation 历史/估算/清除钩子 · provider 通道  │
│           既有虚拟线程池 · 既有读文件/权限设施                    │
└────────────────────────────────────────────────────────────────┘
```

### 加载管线（会话启动一次）

```
项目根/ACODE.md  ─┐
项目根/.acode/ACODE.md ─┼→ 逐个展开 @include（深度上限 + 已展开集合 + 逃逸拦截）
~/.acode/ACODE.md ─┘     → 按固定分隔线拼接（项目根在最前）
                                            ↓
项目级 MEMORY.md ─┐
用户级 MEMORY.md ─┴→ 逐行解析 + 上限截断 → 索引段（项目级在前）
                                            ↓
                     system 提示 = 既有七段 + 项目指令段 + 记忆索引段
                                            ↓
                          会话启动构建一次，会话内字节不变
```

### 会话路径

```
启动（无 --resume）→ 在 <项目根>/.acode/sessions/ 新建会话文件、开追加句柄
启动（--resume）/ 选择会话 → 恢复四步 → 该会话成为活跃会话、续写同一文件
每轮消息 → 追加一行 JSON（先写盘、后更新内存）
上下文压缩 → 整段原子重写该会话文件
退出/EOF/中断 → 关闭句柄（不整存、不新建文件）
列表 → 扫描目录 + 按最后活跃排序 + 过期标记（不删）
```

### 记忆路径

```
每轮 Agent 循环结束（不再调用工具）
  → 后台异步：索引 + 记忆清单 + 最近一轮对话 → 独立模型调用（不带工具）
      ├─ 输出解析失败 → 本轮什么都不做（log）
      ├─ 会话代次已失效（clear/加载过）→ 丢弃结果
      └─ 成功 → 创建/更新/删除记忆文件 + 同步 MEMORY.md 索引
新记忆 → 下个会话启动时随索引段注入
```

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 旧会话格式 | **直接替换、不兼容**：删掉"一会话一 JSON、退出整存、用户主目录"的旧路径与配套的旧格式角色修复逻辑；旧 JSON 文件不再被 `/resume` 列出（用户已确认） |
| 会话目录归属 | 项目级 `<项目根>/.acode/sessions/`，与项目绑定；换项目即换池 |
| 会话 id | 时间戳 + 随机十六进制后缀（防同一秒内创建多个会话碰撞），文件名即 id |
| 时间戳语义 | JSONL 行的 Unix 秒时间戳 = **落盘时刻**（追加时打戳）；不改动既有消息模型（不给消息对象加时间字段）。恢复时的"最后活跃时间"取末行时间戳 |
| 恢复时插入的时间跨度提示 | **不进历史、不落盘**，作为恢复后首轮的轮次提醒注入（与阶段七边界提醒、环境快照同范式）。理由：不污染用户可见历史、不破坏 JSONL 追加语义、天然幂等（重复恢复不会累积多条）——与 prompt.md 字面"插入到对话中"不同，如不认可可改回"作为一条 user 消息落盘" |
| 恢复续写 | 加载会话后**续写同一文件**（不新建）；阶段七的"未新增消息则不重复存档"逻辑随整存模式一起消失 |
| 追加失败 | 写盘异常只告警并继续（内存仍更新），不中断对话；不重试、不阻塞 |
| 整段重写 | 压缩重建走临时文件 + 原子替换，防重写中途崩溃损坏会话文件 |
| 过期处理 | 超期会话**只标记不删**（用户已确认）；不提供自动删除；归档/删除留待后续 |
| 记忆目录 | 修正 prompt.md 的拼写：统一用 `memory`。用户级 `~/.acode/memory/`（偏好/反馈）、项目级 `<项目根>/.acode/memory/`（项目知识/参考）；**各有自己的 `MEMORY.md`**，注入时**项目级在前、用户级在后**依次拼接——与 ACODE.md「项目级排在前」同序 |
| 记忆索引刷新 | **会话启动注入一次、会话内不刷新**（用户已确认）：异步提取出的新记忆下个会话生效，换取前缀字节稳定与 prompt cache 命中 |
| 提取调用形态 | 与阶段七摘要调用同范式：不携带工具、`thinking` 关闭、独立 `max_tokens`、直接经请求构造器（不经会话的历史组装，避免被裁剪/注入轮次提醒）；模型输出结构化操作列表，解析失败即放弃本轮 |
| 提取失败处理 | 不设熔断（与摘要不同）：提取失败不影响对话，静默记日志、下轮再试；同时最多一个提取任务，重叠时跳过本轮 |
| 项目级记忆不可写 | 项目 `.acode/memory/` 不可写时降级为只写用户级 + 告警一行，不阻断 |
| 写回安全 | 文件名白名单化 + 解析后必须落在对应记忆根内（防模型给出的路径穿越）；记忆写回不经工具层、不弹权限确认（属内部机制，但限死在记忆根内） |
| 记忆自动开关 | 配置项控制，默认开启；关闭后无每轮后台调用，手动入口仍可用（用户已确认） |
| 体积上限 | 索引与单个被展开指令文件都有明确上限（数值见 checklist），超限截断 + 警告，不静默丢 |
| 与 prompt cache 的关系 | 本阶段不改阶段七的决策冻结/压缩触发逻辑；记忆与指令只是 system 提示的**新段**，会话内不变 |

## Out of Scope（本阶段明确不做）

- 向量数据库、RAG、语义检索、embedding 索引（prompt.md 明确不做）
- 记忆的自动时效衰减、置信度打分、冲突消解仲裁（仅"同类不重复创建"的提示层约束）
- 跨项目共享的项目级记忆同步/远端存储（项目级记忆是否提交 Git 由用户自己决定，ACode 只提供 `.gitignore` 建议文案，不自动改用户文件）
- 过期会话的自动删除与归档；会话文件的压缩/打包
- 会话搜索（全文检索历史会话内容）与跨会话合并
- 会话文件的多进程并发写保护（本阶段假定单进程独占）
- 记忆索引的增量刷新与热更新（会话内不刷新是已确认决策，不是缺口）
- `ACODE.md` 的语法扩展（条件段、变量插值、通配 include）
- 对 `~/.acode/` 下既有 config/permissions 命名空间的迁移或重构
