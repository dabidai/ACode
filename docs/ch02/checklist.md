- [x] 启动参数 `--resume` 能被解析（打印出「恢复会话模式」字样即可）

## T2 配置模块

- [x] 仅项目级 `.acode/config.yaml` 存在时正常加载生效（DeepSeek 联调已验证）
- [x] `protocol` 填 `anthropic`/`openai` 以外的值（如 `foo`），报错文本包含「protocol」和「anthropic/openai」字样

- [x] 项目级 `.acode/config.yaml` 存在且只覆盖 `model` → 生效的 model 为项目级值，其余字段沿用全局值
- [x] 项目级文件不存在时，全局配置单独生效，无报错

## T3 Provider 抽象

- [x] `FakeProvider` 测试桩能通过统一接口模拟 onDelta/onComplete/onError 三种回调，供上层单测使用

## T4 Anthropic Provider + SSE

- [x] 用录制的事件片段（含 `content_block_delta` 的 `delta.text`、中文文本、多条事件跨 `\n\n`）解析出与原文一致的增量文本
- [x] 片段中的 `delta.thinking` 事件被正确识别且不计入正文输出
- [x] 片段中的 `error` 事件触发对应异常分类（如 429 → RateLimitException）
- [x] 真实请求验证：已用 DeepSeek Anthropic 兼容端点（`https://api.deepseek.com/anthropic`）跑通 AnthropicProvider 完整链路（x-api-key 认证 + SSE 流式 + thinking）；真实 Claude key 留待有 key 时补
- [x] 请求体包含 thinking 参数（AnthropicProviderTest 断言请求 JSON 含 `"thinking":{"type":"enabled"}` 且 `max_tokens` > `budget_tokens`）

## T5 OpenAI Provider + SSE

- [x] 录制片段（多行 `data:` + 中间空行 + `data: [DONE]`）解析出增量文本且正常结束
- [x] 录制片段中的 `data: {"error":...}` 被识别并触发错误分类
- [x] 真实 DeepSeek key 联调：1 轮对话流式完整回复，无报错（已验证）

## T6 重试与错误处理

- [x] mock 返回 429 → 自动重试恰好 3 次，重试间隔 ≈1s、2s、4s（±0.5s），第 3 次仍 429 时最终抛 RateLimitException
- [x] mock 返回 500 → 重试 3 次后抛 ServerException
- [x] mock 返回 200 → 请求只发 1 次，无重试
- [x] mock 返回 401 → 不重试，直接抛 AuthException
- [x] 连接超时（mock 地址不可达）→ 抛 NetworkException，总耗时 ≤ 读超时 + 重试开销

## T7 对话编排

- [x] 估算函数：输入 1000 个 ASCII 字符，估算结果 ≈250 token（±10）
- [x] 设窗口上限为 2000 token，塞入 10 条共 3000 token 的历史 + 新问题 → 请求包含的消息从最早开始被丢弃，直到估算总量 ≤ 2000，请求正常发出
- [x] 单条消息本身超过窗口上限 → 历史全部清空，请求只含当前问题
- [x] 追加消息后 `Conversation` 中消息数正确（n+1）

## T8 会话持久化

- [ ] 对话 3 轮后退出，`~/.acode/sessions/` 出现 1 个 `.json` 文件，内容含全部 3 轮消息
- [ ] 再次启动 1 轮对话退出 → 目录中出现第 2 个文件，第 1 个文件未被修改
- [ ] `--resume` 启动 → 界面恢复显示上次会话全部历史消息
- [ ] 恢复后继续对话 2 轮 → 新会话文件（或恢复的文件）包含恢复前 + 新增的全部消息

## T9 TUI 基础

- [ ] 启动后进入全屏：上部为输出区，底部固定输入行，无滚动残留/重影
- [ ] 输入行按 Shift+Enter 换行，Enter 提交发送
- [ ] 粘贴 20 行代码到输入区，内容一字不丢，可正常发送
- [ ] 输入历史：连续发 3 条消息后，输入框按 ↑ 依次回到前 2 条输入内容，↓ 回到最新
- [ ] 生成中按 Ctrl+C → 当前回复停止，提示「已中断」，输入框可立即输入新问题；再发新问题正常
- [ ] 输入框为空时按 Ctrl+C → 程序退出，终端恢复正常模式（无残留 ANSI 码）
- [ ] 输入 `/quit` → 退出，终端恢复正常模式
- [ ] 输入 `/help` → 列出 `/quit`、`/clear`、`/help` 三个命令及一行说明
- [ ] 窗口调整大小 → 布局跟随刷新，无错位

## T10 流式输出与 Markdown 着色

- [ ] 真实 API 下回车到首个可见字符 ≤ 3 秒（网络正常时，取 3 次平均值）
- [ ] 回复逐字/逐段出现，不是整段一次性打印
- [ ] ```java 代码块在输出区以代码块样式显示（区别于正文），代码块内文本不换色
- [ ] 代码块标记在两次 delta 之间被切开（模拟），着色状态不破（不出现半个颜色码残留在屏幕上）
- [ ] `**加粗**` 显示为加粗（亮色），`# 标题` 显示为标题样式，`` `行内代码` `` 与原文字色不同
- [ ] 普通文本无任何 ANSI 转义码泄漏（屏幕上看不到 `\033[` 字样）
- [ ] 生成结束光标落位正确，输入行可正常继续输入

## T11 /clear 联动

- [ ] `/clear` 后输出区清空、输入框清空
- [ ] `/clear` 后新提问不再引用清空前的旧消息（如先问「我叫小明」，/clear 后再问「我叫什么」→ 回答不包含小明）

## T12 主流程

- [ ] 无 `--resume` 启动 → 新会话，输入第一句话即可收到回复
- [ ] 任意环节报错（配置、网络、认证）→ 界面显示可读中文提示，程序不崩溃，可继续输入

## T12+ /resume 会话选择

- [ ] 对话 ≥2 轮后退出（已生成会话文件），启动后输入 `/resume` → 显示会话菜单（时间戳 + 消息数 + 首条用户消息预览）
- [ ] 会话 ≥2 个时，`↓` / `↑` 切换选中行，选中行反显 + `▸` 标记随之移动
- [ ] 回车加载选中会话 → 界面清空并回显该会话全部历史消息
- [ ] 加载后提问「我是谁」→ 回答引用加载会话的历史（上下文已替换为所选会话）
- [ ] 菜单中按 Esc 或 Ctrl+C → 取消回到正常输入，界面不残留菜单块
- [ ] 无历史会话时输入 `/resume` → 提示「没有可恢复的会话」
- [ ] `/help` 文案包含 `/resume`

## T13 端到端验收 ⚑

- [ ] 真实 Claude key：连续 5 轮对话（含 1 次粘贴代码提问、1 次引用前文的问题）全部正常流式返回
- [ ] 真实 OpenAI key：连续 5 轮对话全部正常流式返回
- [ ] 记忆验证：第 1 轮告知「我叫小明，喜欢乒乓球」，第 3 轮问「我叫什么、喜欢什么」→ 回答正确引用
- [ ] 换用错误 api_key → 界面提示认证失败，不崩溃；改回正确 key（重启）后恢复正常
- [ ] `--resume` 恢复上次 5 轮会话，继续对话 3 轮无异常
- [ ] 项目级配置把 `model` 换成另一型号 → 重启生效（回复风格/长度可感知差异）
- [ ] 全程 `mvn test` 全绿（单元测试 ≥ 15 条，无网络依赖）
