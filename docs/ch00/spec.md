# ACode 阶段四：终端渲染改造（主屏可复制）— spec

> 最后更新：2026-08-14

## 背景

ACode 的界面自始采用「备用屏幕 + 全屏重绘 + 自绘滚动条 + 鼠标捕获」渲染：进入备用屏幕缓冲、每帧按 shadow-diff 全屏增量刷新、拦截鼠标滚轮与点击驱动自绘滚动条。这套架构换来了「滚动与界面完全受控」，却付出一个关键代价——**输出无法用鼠标划选复制**。备用屏幕屏蔽了终端的原生 scrollback 与选择，鼠标捕获让点击选中彻底失效，每帧重绘会打断进行中的选择。

Claude Code 选择了相反的架构：**主屏幕 + 追加进原生 scrollback + 仅重绘底部活跃区**。已完成的内容只打印一次、进入终端原生回滚，天然可选中、可复制、可滚动；流式回复与工具卡片作为「活跃区」在屏幕底部原地更新，不触碰上面的历史。本阶段把 ACode 的渲染层切换到这个架构，使输出可复制，并顺势删掉自绘滚动条与视口逻辑这套为全屏重绘服务的旧设施。

## 目标用户

- 本人：在终端里日常使用 ACode，需要复制模型输出（代码、报错、路径）贴回编辑器或别处
- 后续阶段的潜在使用者：终端开发者、习惯命令行工作流的用户——「输出能选中复制」是命令行工具的基本预期

## 能力清单

1. 主屏渲染：不再进入备用屏幕，输出直接写主屏幕缓冲，进入终端原生回滚
2. 追加式历史：已完成的内容（用户输入、回复、终态工具卡片）只打印一次进入回滚，可划选、可复制、可滚动
3. 活跃区局部重绘：流式回复与工具卡片状态变化只在屏幕底部活跃区内原地更新，不重绘历史
4. 原生回看：滚轮、翻页键、鼠标拖动滚动条全部由终端原生处理，应用不再自绘滚动条、不再维护视口
5. 释放鼠标：应用不再捕获鼠标事件，划选复制全程可用且不被重绘打断
6. 活跃区会话菜单：会话选择菜单在活跃区渲染，不进入回滚，选定/取消后消失
7. 窗口缩放回流：尺寸变化由终端原生回流，内容不丢失、不错位
8. 输入无回声残留：提交的内容由应用统一追加，屏幕不出现输入原文与追加行双写
9. 恢复会话可复制：resume 恢复的历史以追加方式渲染，与本次会话内容一样可复制

## 非功能要求

- 追加一致性：每次输出以换行收尾、光标停在行首，全程不依赖绝对定位转义
- 光标契约：活跃区重绘只使用相对移动与清屏序列，与输入组件的光标模型自洽，输入框不错位
- 超长回复：回复超过一屏时只重绘可见后缀，已滚入回滚的顶部不再改动（边界可能存在少量旧渲染残留，属架构固有）
- 可测试：折行、上移行数、可见后缀、写序列等重绘计算为纯函数，单元测试不依赖真实终端
- 兼容性：对话、工具调用、Agent 循环、会话持久化等既有功能行为不变；全量单测保持绿色
- 删除彻底：旧的全屏重绘、自绘滚动条、鼠标捕获相关代码与测试一并移除，不留死代码

## 设计骨架

### 分层结构

```
┌───────────────────────────────────────────────┐
│  UI 层：流式文本、工具卡片、进度与终止提示      │
├───────────────────────────────────────────────┤
│  渲染层：已提交内容追加 + 活跃区局部重绘        │
├───────────────────────────────────────────────┤
│  内容模型：逐行保存的输出区（纯模型，不绘制）   │
├───────────────────────────────────────────────┤
│  终端层：主屏幕输出（原生回滚 / 选择 / 滚轮）   │
├───────────────────────────────────────────────┤
│  输入层：行编辑器（无鼠标捕获，回车/多行/粘贴） │
└───────────────────────────────────────────────┘
```

- **渲染层**是本章新增核心：区分「已提交内容」与「活跃区」。前者追加打印一次、永不改动；后者随事件原地重绘。
- **内容模型**只保存已提交的逐行内容（供测试与恢复渲染），不再有滚动偏移等视口状态。
- **终端层**瘦身为生命周期壳：打开/关闭/尺寸/写入，不再做任何整屏绘制。
- **输入层**去掉鼠标拦截，仅保留键盘输入；提交时擦除原输入行，由渲染层统一追加。

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 渲染架构 | 主屏幕 + 追加进原生 scrollback + 仅重绘底部活跃区 |
| 历史查看 | 完全原生化：删除自绘滚动条与视口逻辑，滚动/选择全走终端 |
| 鼠标 | 不再捕获，原生划选/滚轮全程可用 |
| 活跃区更新 | 光标上移旧活跃区行数 → 清到屏尾 → 打印新内容；行数按显示宽度折行计算 |
| 超长回复 | 仅重绘可见后缀（从底部倒数）；已进回滚的顶部不再改动，边界可能存在少量旧渲染残留 |
| 光标锚点 | 每次输出以换行收尾停于行首；输入提交时擦除原输入行，由应用统一追加 |
| 活跃区与已提交 | 内容模型持续更新：流式回复随增量替换尾部、工具卡片在终态时提交一次；「活跃区清空」只重置重绘状态，屏幕文本保留为历史 |
| 工具卡片 | 进行中卡片仅在活跃区渲染、不进入已提交；工具执行完成时终态卡片提交一次进入回滚；运行中卡片被滚入回滚属接受的边界残留 |
| 会话选择菜单 | 活跃区覆盖渲染，不进入回滚 |
| 窗口缩放 | 终端原生回流，应用不清屏；活跃区重绘在宽高变化时先把已渲染的行数归零再重画（reflow 后旧行数失效） |
| 配置 | 不新增配置项；删除项均为渲染实现细节 |

### 渲染数据流

```
用户输入（输入层提交，原输入行被擦除）
  → 渲染层把「● 用户输入」追加进已提交内容（打印一次，进入原生回滚）
  → Agent 循环事件到达：流式文本增量 / 工具卡片状态变化
  → 渲染层重绘底部活跃区：
      光标上移旧活跃区行数 → 清到屏尾 → 打印新活跃区内容（每段以换行收尾）
  → 循环结束：活跃区重绘状态归零、文本保留（回复与终态卡片已是屏幕底部历史），光标停于内容下方行首
  → 下一轮输入（输入层重新绘制提示行）
```

### 内容模型与持久化

- 内容模型保留逐行文本，作为已提交内容的快照来源（测试断言、resume 恢复渲染）；流式回复随增量替换尾部、终态工具卡片在完成时写入
- 会话保存/恢复沿用现有机制，不受渲染改造影响；恢复的历史以追加方式渲染为可复制文本

## Out of Scope（本章明确不做）

- 应用内分页回看（滚动回看全部由终端原生 scrollback 承担）
- 流式渲染节流优化（如手测出现卡顿再另行评估）
- 真彩色 / 图片 / 超链接等富文本渲染
- 多标签 / 多会话分屏
- 异常终端（dumb、无光标绘制能力）的降级渲染
- 复制内容格式定制（如复制为 Markdown / 去 ANSI）
- 退出时终端 raw 模式的完整恢复增强（现状保留为观察项）
