# 架构风险修复计划

## 目标
修复权限白名单绕过、MCP 断线重复执行、记忆重置写回竞态、取消后旧工具副作用四项风险。每项独立验证、独立提交并推送 GitHub。

## 阶段
- [complete] 1. 确认需求边界，更新根目录规格、任务、验收文档
- [complete] 2. 修复安全命令判定，测试、提交并推送
- [in_progress] 3. 修复 MCP 重试语义，测试、提交并推送
- [pending] 4. 修复记忆提取重置竞态，测试、提交并推送
- [pending] 5. 修复取消后的工具生命周期，测试、提交并推送
- [pending] 6. 全量回归、端到端验证与提交记录核对

## 约束
- 不修改数据库。
- 不覆盖其他任务的未提交文件；每次只暂存本项文件。
- 先验证后提交，每项推送到 origin。
- MCP 与取消策略以用户答复为准；未答复时采用避免重复副作用的保守语义。

## 已知环境问题
- 受限沙箱中的全量 Maven 测试会遇到临时目录和日志目录权限问题，不能把其失败数直接视为代码回归。
