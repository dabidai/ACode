# ACode 阶段八：工具结果展示策略（只读摘要 + 写入 diff）— spec

> 最后更新：2026-08-17

## 背景

阶段六（ch06）把工具执行结果一律渲染成输出块（`⎿` + 缩进内容 + 耗时脚注）。其中 `ReadFile` 把整个文件内容（上限 300 行）原样刷进回滚——读大文件时屏幕被挤占、回滚难翻。用户要求按工具性质分级展示：

1. **只读工具**（ReadFile/Glob/Grep）成功时不列内容，只显示一行摘要 + 耗时；
2. **写入工具**（WriteFile/EditFile）显示红绿 diff 对比（新增绿 `+`、删除红 `-`），便于核对写入了什么；
3. **Bash** 维持现状（需要看到命令输出）。

目标：区分「读结果」与「写结果」的展示——读只给结论、写给对比。模型回传内容不变（仍是各工具现有正文），展示层另有独立正文。

## 目标用户

- 本人：长时间终端会话中不希望被大段文件内容刷屏；但写入操作需要看到实际改动以核对
- 后续阶段潜在使用者：终端开发者、习惯命令行工作流的用户

## 能力清单

1. ReadFile 成功：展示一行摘要「返回 N 行（Lx-y）」带行号范围 + 耗时脚注，不列文件内容
2. Glob 成功：展示一行摘要「返回 N 个匹配」+ 耗时脚注，不列路径列表
3. Grep 成功：展示一行摘要「返回 N 条命中」+ 耗时脚注，不列命中行
4. 只读结果被截断时，摘要末尾追加「（已截断）」提示
5. WriteFile 成功：展示首行确认 + 行级红绿 diff（`+` 新增绿、`-` 删除红）；新建文件全 `+` 行
6. EditFile 成功：展示首行确认 + 每段替换的 `- 旧文` / `+ 新文` 对比行（多行段按行拆分）
7. diff 仅界面展示：模型回传的 `tool_result` 内容不变（仍是简短确认）；`--resume` 历史渲染不受影响
8. 失败结果一律照常显示错误（只读/写入均如此）
9. Bash、AskUser、ExitPlanMode 的展示行为不变
10. 可测试：摘要文案、diff 生成、展示层着色均有单测，端到端可脚本化（FakeProvider）

## 非功能要求

- **模型 payload 不变**：展示用正文与回传用正文分离，仅界面层消费展示正文；对话历史与持久化只存回传正文
- **大文件安全**：diff 上限以「变更规模」计——先裁共同前缀/后缀、仅对变更中段做 LCS，文件整体多大都不影响是否出 diff；仅变更本身过大时降级为「（变化过大，省略对比）」。WriteFile 写前读旧内容设大小守卫（超大文件直接省略对比），EditFile 变更超展示上限省略对比，写操作不被 diff 拖慢、不爆内存
- **写操作韧性**：WriteFile 旧内容读取失败（非 UTF-8 等）或超大（超过大小守卫）不阻断写入，display 降级提示，文件写入与模型回传照常
- **追加式兼容**：渲染仍走追加式（每行一次写屏进回滚），无光标重绘，宽度失配不可能错位
- **通用着色**：展示层按行前缀着色（`+` 绿 / `-` 红），不依赖工具名硬编码，未来工具自动适用
- **可测试**：全链路单测无网络依赖

## 设计骨架

```
┌──────────────────────────────────────────┐
│ UI 展示层：工具卡片终态渲染               │
│   · 展示正文非空 → 渲染展示正文（替代回传） │
│   · 展示正文为空 → 渲染回传正文（现行为）   │
│   · 行前缀 `+ ` 绿 / `- ` 红，通用着色      │
├──────────────────────────────────────────┤
│ 事件订阅层：结果事件透传展示正文            │
│   · 订阅方重建结果对象时把展示正文带上      │
├──────────────────────────────────────────┤
│ 执行器层：结果经事件队列传出，展示正文随行  │
├──────────────────────────────────────────┤
│ 工具层：                                 │
│   只读工具（ReadFile/Glob/Grep）→ 一行摘要  │
│   写入工具（WriteFile/EditFile）→ 确认+diff  │
│   其余工具（Bash/AskUser/ExitPlanMode）→ 不填 │
│   失败路径 → 不填（错误照常显示）            │
└──────────────────────────────────────────┘
```

工具层产展示数据（摘要 / diff 文本行），UI 层只按前缀着色消费；display 与回传 content 解耦，不回流模型、不进持久化。

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| ReadFile 摘要 | 「返回 N 行（Lx-y）」带行号范围 + 耗时脚注；被截断时加「（已截断）」 |
| 写入显示 | 行级红绿 diff：`+` 新增绿、`-` 删除红；首行保留确认文案 |
| 作用范围 | 所有只读工具（ReadFile/Glob/Grep）；Bash 维持现状 |
| 展示分离 | 展示正文仅界面层消费，模型回传与持久化不变 |
| 失败展示 | 一律显示错误正文，不套用摘要/diff |
| diff 范围 | 行级；先裁共同前缀/后缀、仅对变更中段做 LCS；超限降级提示，不做行内字符级 |
| diff 上限 | 以变更行数为准（checklist 定具体值）；文件整体大小不影响是否出 diff；EditFile 变更超展示上限省略对比 |
| diff 计算方 | 写入工具在执行时计算（此时旧内容仍在磁盘），渲染层只按前缀着色 |
| 旧内容读取 | 大小守卫（checklist 定值）超限不读、读取失败不阻断写入；均降级提示 |

## Out of Scope（本章明确不做）

- 语法高亮、左侧行号、整行背景色（ch05/ui.md 的完整 diff 需求，另立阶段）
- 行内（字符级）diff：EditFile 只做每段 old/new 的行级展示
- 摘要行「点击展开」交互；diff 折叠 / 分页 / 一键回滚
- Bash 输出展示变更；AskUser / ExitPlanMode 展示变更
- 只读摘要文案的个性化配置
