# Windows 终端输入框缩放修复：结论与经验

## 用户可见结果

ACode 的等待输入区现在由模式行、上边线、输入内容、下边线和模型信息组成。正常视口中，这五层作为一个整体贴在终端底部。输入换行或折行时，编辑区占用上方预留空间；连续缩窄、放大窗口不会再留下旧的 `[default]` 和横线。已输入的文字在缩放后保持完整，一次回车只提交一次。

原生 CMD、PowerShell 和 Windows Terminal 均完成了启动、缩放、`abc` + 缩放 + `def`、Shift+Enter 多行和退出后历史回看的真机检查。CMD 的 `/quit` 和 Ctrl+C、另外两种终端的 `/quit` 均正常返回 shell。自动化回归为 **1134 tests、0 failures、0 errors、1 skipped**。

## 这次定位到的原因

1. **一个输入框不能由两个光标模型共同维护。** 早期版本让 JLine 多行提示符绘制上半部，让 JLine `Status` 绘制下半部。Windows 缩放会先回流旧字符，再通知程序尺寸变化。JLine 重建内部 `Display` 后，仍无法删除已经进入真实终端回滚区的旧模式行和横线。仅提高 JLine 版本、只刷新提示符、或在 JLine 重绘前手动移动光标，都未通过真实 CMD 检查。
2. **活动读取期间不能用 CPR 查询位置。** CPR 回复和用户按键走同一个输入流；回复曾被 JLine 当作输入，屏幕出现 `;;3R` 等残字。120ms 尺寸轮询也曾和 JLine 的 WINCH 处理同时绘制，造成双重重绘。
3. **状态区编辑期间不能反复改变高度。** 首版把五层全部交给 `Status` 后，Shift+Enter 每增加一行就改变滚动区域。真实 CMD 中旧输入被遮掉，边线没有同步上移。当前实现按窗口高度预留稳定的底部区域，输入在空白行中向上展开；超出可见容量时只显示光标附近的输入，缓冲区保留全文。
4. **清理顺序属于终端协议的一部分。** `/quit` 曾先关闭 `Terminal`，再调用 `Status.close()` 恢复滚动区域，抛出 `Terminal has been closed`。现在先恢复滚动区域，再关闭终端。
5. **终端类型不能把空白环境值当成有效名称。** Windows CMD 中空白的 `TERM` 曾触发 JLine 调用系统不存在的 `infocmp`。现在把空白 `TERM` 视为未指定，并注册内置 Windows 能力表。

## 当前绘制方式

- JLine 继续负责按键、历史、补全和编辑缓冲；五层输入框由同一个底部 `Status` 绘制。
- WINCH 期间清除旧回流画面，从 `OutputPane` 重放已提交的 ACode 输出，再绘制当前输入框。一次尺寸变化只走一条重绘链，不发送 CPR，也没有轮询线程。
- Windows 原生终端不捕获鼠标。用户选择保留 CMD 的鼠标拖选复制；用终端原生滚轮浏览旧视口时，输入框随整个视口移动，滚回最新画面后重新贴底。

## 已知边界

- 缩放重建只重放 `OutputPane` 当前保存的最近 **2000 行** ACode 输出。启动 ACode 之前的 shell 回滚内容可能被清除；用户确认只需保留 ACode 对话。
- 超出底部预留区容量的输入仍完整留在编辑缓冲，屏幕显示光标附近的部分。150 字符加 12 行、跨缩放后完整提交已由自动化测试覆盖；超长输入的真实终端视觉效果尚未单独验收。
- Ctrl+D 退出仍未做真实终端复核。

## 下次修改的验证顺序

1. 先运行 `mvn test`，再用新打包的 `target/acode.jar` 做真机检查；虚拟终端不能模拟 Windows 控制台的回流和 QuickEdit。
2. 在 CMD、PowerShell、Windows Terminal 中分别缩窄、放大窗口，检查屏幕只剩一份五层输入框。
3. 输入 `abc`，缩放，再输入 `def` 回车；只应提交一次 `abcdef`。再用 Shift+Enter 检查两行文本与上下边线。
4. 在 CMD 中确认鼠标拖选复制；滚轮回到最新画面后输入框贴底。
5. 用 `/quit`、Ctrl+C 和 Ctrl+D 检查 shell 提示符、终端滚动区域和退出后的 ACode 对话历史。
