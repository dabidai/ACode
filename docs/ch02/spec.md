# ACode 阶段二：工具调用 — spec

> 最后更新：2026-08-13

## 背景

ACode 已完成对话层（阶段一）：全屏 TUI、流式输出、多轮记忆、会话持久化、双后端。但从模型视角它仍是「聊天机器人」——只会说话，不能动手。

本阶段加入工具调用：模型可以读文件、写文件、改文件、执行命令、搜索代码。配合**完整单步闭环**（模型发起工具调用 → ACode 执行 → 结果回传 → 模型给出最终回复），ACode 从「能聊」变为「能干活」。

单步闭环是刻意收敛的范围：本章只支持**一轮**工具调用（每轮对话最多两次请求），连环调用与自主循环留到下一章。

## 目标用户

- 本人：在终端里让 AI 真正改代码、查代码，而不是只会给建议
- 后续阶段的潜在使用者：终端开发者、愿意接受命令行工作流的用户

## 能力清单

1. 统一工具接口：每个工具实现同一接口，暴露名称、描述、参数定义、权限级别
2. 通用基类：参数校验、超时包装、异常转结果等公共逻辑收敛到基类
3. 执行结果模型：成功/失败、正文输出、是否错误标记，统一回传格式
4. 注册中心：集中注册、启用、禁用、查询工具，并可整体转换为后端 API 的 tools 参数格式
5. 读文件：按路径读取文本文件内容，支持限定行范围与超长文件截断
6. 写文件：覆盖写整个文件，自动创建缺失的父目录
7. 改文件：一次调用内做多段精确替换，任一段失败则整体失败、文件不动
8. 执行命令：以 Bash 语义执行 shell 命令，Windows 上优先 Git Bash、回退系统默认 shell，带超时与输出截断
9. 匹配文件路径：按 glob 模式列出匹配的文件路径
10. 搜索内容：按正则搜索文件内容，返回命中位置与行内容
11. Anthropic 请求侧：请求体携带工具定义，消息内容升级为结构化块
12. Anthropic 响应侧：流式解析 tool_use 块，JSON 参数碎片逐段拼接成完整 JSON
13. 完整单步闭环：检出工具调用 → 串行执行 → 结果以 tool_result 回传 → 再发一次请求 → 模型输出最终文本
14. 工具调用可视化：终端展示工具名、参数摘要、执行状态（进行中/成功/失败）与结果摘要
15. 上下文与持久化联动：工具调用与结果计入对话历史，参与超限截断，会话保存/恢复完整保留

## 非功能要求

- 工具执行有超时：命令执行类默认秒级、可配置，文件操作类更短；超时后终止并返回超时错误
- 工具输出有上限：过长结果截断后回传，进入历史前同样截断，避免撑爆上下文
- 工具失败/超时不中断流程：作为带错误标记的结果回传模型，由模型在最终回复中处理
- 单步闭环有硬上限：每轮对话最多两次请求，第二次仍请求工具时只取文本并提示
- 生成过程中输入框不被阻塞，Ctrl+C 可中断工具执行
- 多工具调用按声明顺序串行执行，不做并发
- 核心逻辑（工具、注册中心、消息模型、流式解析、闭环编排）有单元测试，不依赖真实网络
- 会话文件能完整往返含工具块的消息（重启后上下文不丢）

## 设计骨架

### 分层结构

```
┌───────────────────────────────────────────────┐
│  UI 层：工具调用卡片（名称/参数/状态/结果摘要） │
├───────────────────────────────────────────────┤
│  编排层：单步闭环（最多两轮请求）               │
│  tool_use 检出 → 执行 → tool_result 回传        │
├───────────────────────────────────────────────┤
│  工具层：Tool 接口 / 基类 / 注册中心            │
│  ReadFile WriteFile EditFile Bash Glob Grep     │
├───────────────────────────────────────────────┤
│  Provider 层：Anthropic 工具协议                │
│  请求 tools + content block / 响应 tool_use 流式 │
├───────────────────────────────────────────────┤
│  消息模型层：content block（text / tool_use /   │
│  tool_result）→ 会话持久化                      │
└───────────────────────────────────────────────┘
```

- **工具层**不感知 Provider 与 UI：工具只接收结构化参数与执行上下文、返回结果；错误以「结果形态」返回（带错误标记），不抛给上层。
- **编排层**是唯一知道「一轮闭环」的地方：把 tool_use 转成执行请求、把结果转成回传消息、控制最多两轮请求。
- **Provider 层**只负责协议：请求侧把统一工具定义转成后端 tools 格式、把统一消息块转成后端 content 格式；响应侧把后端流事件转成统一回调。
- **消息模型层**是全局底座：content block 被 Provider 请求/响应、上下文截断、会话持久化共同消费。

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 闭环边界 | 完整单步：tool_use → 执行 → 回传 → 第二次请求 → 最终文本 |
| 请求上限 | 每轮对话最多两次请求，防连环调用失控 |
| 消息模型 | 结构化为 content block（text / tool_use / tool_result） |
| 后端范围 | 本章先 Anthropic，OpenAI 下章 |
| Bash 执行器 | 检测 Git Bash，回退系统默认 shell |
| 权限 | 工具带 read/write/exec 元信息标记，本章不拦截不确认 |
| 并发 | 多个工具调用按声明顺序串行执行 |
| 失败语义 | 失败/超时 → 带 is_error 标记的 tool_result 回传模型 |
| 结果截断 | 回传前与入历史前都截断超长结果 |
| 文件编辑 | 不做自动备份/回滚（依赖 git 版本控制） |
| 思考模式 | 与工具调用兼容：thinking 块不展示、不影响工具块累积 |

### 单步闭环数据流

```
用户提问
  → 请求①（携带全部工具定义 + 完整历史）
  → 模型流式返回：文本块 + 可选 tool_use 块（JSON 碎片拼接）
  → 无 tool_use：文本直接展示并保存（回归阶段一行为）
  → 有 tool_use：
      UI 展示工具调用卡片
      按声明顺序串行执行（超时/失败 → 结果带错误标记）
      UI 更新执行结果
      追加 tool_result 消息到历史
      请求②（历史含工具结果）
      → 模型返回最终文本 → 展示并保存
  → 请求②仍返回 tool_use：不执行，仅取文本展示并提示「连环调用未支持」
```

### 配置模型

沿用现有 YAML 两级配置。可选的工具控制字段：按工具名启用/禁用，缺省全部启用。不引入新的配置来源。

### 上下文与持久化

- 工具调用与结果作为结构化消息计入历史，token 估算与超限丢弃逻辑覆盖 content block
- 超长工具结果在进入历史前截断
- 会话文件保存完整 content block；恢复时工具块以一行摘要展示，用户可继续对话

## Out of Scope（本章明确不做）

- Agent 循环：连环工具调用（第二次请求仍请求工具时只取文本）
- 权限系统：确认/拒绝流程、危险命令拦截（仅定义元信息标记）
- 并发执行：多个工具串行，不做并行
- OpenAI 工具调用协议（tool_calls delta）
- MCP（Model Context Protocol）接入
- 文件编辑的撤销/回滚与自动备份
- 工具结果的分页/折叠交互、历史工具调用的回放浏览
- 超出工具参数之外的模型输出校验（信任模型）
