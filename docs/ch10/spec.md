# ACode 阶段十：Skill 系统 — 规格

## 背景

ACode 已有可运行期注册的命令、工具注册表、Agent 循环、提示词拼装和会话生命周期，但可复用操作仍写在代码里。用户需要以文件定义任务指引，通过命令或自然语言调用，并在执行时限制模型可用的工具。现有权限检查仍是所有工具执行的最终边界。

## 目标用户

- 日常使用者：直接调用提交、测试等常用流程，按项目习惯修改指引。
- 团队成员：把项目指引放入仓库，让同一项目共享操作约定。
- 后续阶段：复用 Skill 的独立执行接口，对接 SubAgent 运行时。

## 能力清单

- 用户可用带元信息的 Markdown 文件定义 Skill；文件正文是按需加载的任务指引。
- 系统从项目、用户和内置资源查找 Skill，同名时按项目、用户、内置的顺序覆盖。
- 单个无效 Skill 不妨碍其他 Skill 和主程序启动；配置冲突有可见告警。
- 启动时只把 Skill 名称和描述组成索引放入系统提示；没有 Skill 时不增加索引段。
- 用户可通过同名斜杠命令调用 Skill，也可让模型通过加载工具按意图激活 Skill。
- Skill 正文在激活后作为独立消息进入会话；模型调用的工具结果保持完整配对和正确顺序。
- 同一会话支持按需加载多个 Skill；同一版本避免重复注入，正文变更后再次调用会注入新版本并标明它取代旧版本。
- Skill 可引用同目录的脚本、参考资料和资产；资源由模型按正文指引取用。
- Skill 可声明工具范围；范围同时约束模型可见工具和实际工具执行，并继续接受既有权限检查。
- Skill 可声明请求级模型选择；不改变会话默认模型。
- 用户可查看 Skill 列表、来源与定义，并显式重扫文件及同步命令和提示索引。
- 已发现 Skill 的正文变更在下次调用时生效；读取失败可使用同一来源的最近一次有效版本。
- 清空、压缩重建和恢复会话后，激活状态与历史保持一致；失效时提示重新加载。
- 内置提供提交与测试两种 Skill，作为可编辑覆盖的日常流程和自定义示例。
- 独立上下文执行保留接口；在 SubAgent 阶段完成前，调用该模式会得到明确的未实现结果。

## 非功能要求

- 不新增第三方依赖；解析、扫描、合并和过滤逻辑可脱离终端测试。
- 保持已有命令、权限模式、Plan 模式、MCP 工具与会话文件兼容。
- 重载时命令、提示索引和来源信息一致；执行中的 Skill 使用已确定的快照。
- 项目文件中的 Skill 正文按外部指引处理，不提升为系统或开发者指令。
- 错误可定位到 Skill 和来源；单份文件异常不影响会话继续。

## 设计骨架

1. **发现层**读取元信息、确定同名覆盖关系，形成稳定排序的索引；内置资源使用可枚举的索引或等价清单。
2. **运行层**管理一次激活的定义快照、工具范围、请求模型与历史有效性，供命令和加载工具共用。
3. **Agent 接点**在请求前计算可见工具和模型，在执行前再次核验允许的工具；Plan 模式限制与权限检查始终有效。
4. **历史接点**先记录完整的一批工具结果，再追加本批成功加载的正文；命令调用走现有对话入口。取消或历史代次变化时不留下半激活状态。
5. **生命周期接点**联动清空、压缩和会话恢复；重载采用一致的仓库与命令快照。
6. **跨章接点**仅定义独立执行委托形状，实际子 Agent 创建、上下文选择和结果回传留给阶段十二。

## Out of Scope

- 真正运行独立上下文的 Skill。
- 为 Skill 自动注册专属工具，或自动读取其资源目录的全部内容。
- Skill 市场、远端安装、版本管理与跨设备同步。
- 仅凭 Skill 白名单替代现有权限系统，或允许项目 Skill 绕过 Plan 模式。
- 改造现有审查命令和其他阶段的功能。
- 对恢复历史中的旧 Skill 正文做身份推断与去重。
