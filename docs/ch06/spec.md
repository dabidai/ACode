# ACode 阶段六：工具结果渲染（Claude Code 式命令输出展示）— spec

> 最后更新：2026-08-16

## 背景

阶段五（ch05）接入工具权限确认后，工具调用链完整但展示粗糙：`ToolCallDisplay` 把工具结果渲染成单行折叠卡——运行行「⏳ 调用工具 X(params)」+ 终态行「▸ X(params) 成功/失败：<200 字符压缩预览>」。多行输出（Bash 日志、WriteFile 回显）被压成一行难读；命令与输出不易分辨；无耗时信息。

用户对照 Claude Code 的终端体验，在 `docs/ch05/ui.md` 提出四项 UI 需求（结果渲染 / 选择交互 / Diff / 多终端），并确认**逐个立阶段**。本阶段（ch06）只做第一项：**工具执行结果渲染**——按 Claude Code 样式渲染成「● 命令 + 缩进多行输出块 + 耗时脚注」。

## 目标用户

- 本人：需要在终端看清命令输出、分辨工具与结果、感知耗时的 AI 编程助手用户
- 后续阶段潜在使用者：终端开发者、习惯命令行工作流的用户

## 能力清单

1. 运行行：工具发起时渲染「● Name(params)」（参数沿用紧凑摘要），替换「⏳ 调用工具 Name(params)」
2. 输出块：工具完成时把结果按多行块渲染——首行「  ⎿  <内容行>」按成败着色（成功绿 / 失败红），后续行「     <内容行>」对齐缩进、原色展示
3. 状态去字：去掉显式「成功/失败」文字，以首行颜色区分成败
4. 耗时脚注：输出块末尾追加「  ⎿  (<耗时>)」——<1s 显示毫秒（如 823ms），≥1s 显示秒带一位小数（如 2.3s）
5. 截断保护：单条工具结果超过显示上限（300 行）时截断，末尾补「…（输出过长，已截断）」
6. 空结果兜底：无返回内容时渲染「（无返回结果）」占位，不产生空块
7. 耗时归属：耗时为工具实际执行时长，不含用户确认等待；确认拒绝 / 取消路径记 0
8. 追加式兼容：输出块逐行追加进回滚，每行只写一次，无光标重绘、可划选
9. 可测试：渲染为纯函数（输入结果 + 耗时 → 输出行），主流程接线有单测覆盖

## 非功能要求

- 无回归：存量卡片生命周期（appendRunning → appendDone → flushCards 追加式写屏）语义不变
- 可观测：命令、输出、耗时都可见，用户能分辨「工具发了什么、返回了什么、花了多久」
- 防刷屏：单条结果 300 行上限 + 截断 marker，Bash 内部已有的 30000 字符截断之上再兜一层
- 可测试：渲染纯函数、主流程平行记录均有单测，不依赖真实网络与真实终端
- 无性能负担：耗时用 `System.nanoTime` 测得，仅毫秒级换算，对工具执行无感知开销

## 设计骨架

### 分层结构

```
┌────────────────────────────────────────────┐
│ UI 层：ToolCallDisplay（● 行 + 输出块 + 脚注）│
│         StreamPrinter（终态追加进回滚）        │
├────────────────────────────────────────────┤
│ 事件订阅层：ConversationController           │
│   事件循环平行记录 results / elapsedList     │
├────────────────────────────────────────────┤
│ Agent 层：ToolResultEvent 携带 elapsedMs     │
├────────────────────────────────────────────┤
│ 执行器层：StreamingToolExecutor.runCall      │
│   nanoTime 包裹 executor.execute 测耗时      │
├────────────────────────────────────────────┤
│ 工具层：ToolResult（成功/失败 + 内容）        │
└────────────────────────────────────────────┘
```

### 关键设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 运行行 | 「● Name(params)」替换「⏳ 调用工具 Name(params)」；工具名青色（复用 STYLE_NAME） |
| 输出块 | 首行「  ⎿  <内容行>」按成败着色（绿/红），后续行「     <内容行>」对齐、原色 |
| 状态字 | 去掉显式「成功/失败」文字，以首行颜色区分 |
| 耗时脚注 | 末尾「  ⎿  (<耗时>)」；<1s→毫秒（823ms），≥1s→秒（2.3s） |
| 耗时归属 | 仅统计 executor.execute 执行时长，不含确认等待；拒绝/取消记 0 |
| 截断 | 单条结果 >300 行截断，补「…（输出过长，已截断）」 |
| 空结果 | 无内容 → 「（无返回结果）」占位行 |
| 模型可见性 | 运行行不进模型；终态输出块进模型（多行），供历史/续聊保留 |

### 渲染数据流

```
StreamingToolExecutor.runCall
  → long start = System.nanoTime() 包裹 executor.execute(call)
  → ToolResultEvent(toolId, toolName, output, isError, elapsedMs) 入队
       （确认拒绝路径 elapsedMs=0）
ConversationController.handleExchange 事件循环
  → ToolResultEvent 分支同时记 turnResults 与 elapsedList（声明序对齐）
  → TurnComplete / LoopComplete → printer.updateToolCalls(results, elapsedList)
ToolCallDisplay.appendDone(result, elapsedMs)
  → 生成输出块行（首行 ⎿ 绿/红 + 后续行缩进 + 截断 marker + ⎿ 耗时脚注）
  → StreamPrinter.updateToolCalls 写入内容模型 → flushCards 逐行追加进回滚
```
