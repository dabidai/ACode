## 默认值说明（实现与测试必须与此一致）

**预算常量**
- 单工具结果可见保留上限：`50_000` 字符。正文长度**恰好等于**该值时全文保留（不落盘）；**超过**才落盘替换
- 同批聚合上限（单条 tool_result user 消息合计）：`200_000` 字符；批内从未落盘的最大者开始替换，直至合计 ≤ 上限
- 落盘预览长度：正文前 `2_048` 字符
- 摘要输出预留：`20_000` token；自动压缩安全余量：`13_000` token
- 自动压缩触发点 = `maxContextTokens − 20_000 − 13_000`（窗口默认 200_000 → `167_000`；例如配置 128_000 → `95_000`）
- 保留尾预算：`8_000` token（按完整轮次从尾部装入；连一个完整轮次都装不下时保留尾为空）；**不可压缩仅未闭环步**：最新未答复 user 原文 + 最末尚无结果的 assistant tool_use（结果已回填则整对保留）——**已闭环轮次属普通历史、可进摘要区**（长请求内连续多轮也可中途压缩）
- 重建后整体估算（摘要 + 边界 + 保留尾，含 system/环境，与触发判断同一口径）≤ 自动压缩触发点；压缩成功后紧接着的自动触发判断为假（不连环再压）
- token 估算沿用现有口径：文本长度 ÷ 4；估算对象 = 系统提示 + 环境快照 + 全部历史消息（分块计：文本/工具参数/工具结果都计入）

**落盘**
- 目录：`<工作目录>/.acode/tool-results/`；文件名 = 对应工具调用 id，扩展名 `.txt`
- 幂等：目标文件已存在 → 不覆盖、原样复用（等价 `wx` 创建语义）
- 预览文本（供模型识别，常量文案含以下三要素）：完整结果已存至的文件路径 + 可用读文件工具取回全文的指引 + 省略标记
- 现行一刀切截断后缀 `…（结果过长，已截断）` 不再出现在新流程写入的历史里

**摘要**
- 摘要指令须显式要求以下能力，测试以关键词断言 prompt 含：9 段结构化输出；用户消息尽量原文保留；当前工作最详细；待办与下一步；先起草（丢弃）再成文两阶段；只输出纯文本、禁止调用任何工具
- 摘要请求不携带工具、thinking 关闭（捕获请求的 tools 为空、thinking=false）；max_tokens 用独立常量（默认 `20_000` = 摘要输出预留；若模型单次输出上限更低则取上限）——**不得沿用对话级 `8_192`**（会把长摘要截断）
- 摘要成功 → 历史原地重建：user 摘要消息 + 独立一条 assistant 边界提醒消息（文本——提醒模型"以上为摘要，具体文件内容请用读取工具重新读取、勿凭摘要猜测代码细节"）+ 保留尾（预算内近期完整轮次 + **未闭环步逐字**：最新未答复 user 原文 + 最末尚无结果的 assistant tool_use 整对）；不写死首条角色，断言不变量：全段无同角色相邻、请求以 user 结尾、无悬空 tool_use/tool_result、重建后整体估算（含 system/环境）≤ 触发点
- 用户消息"原文优先"是优先级指引而非硬性逐字全量：不设系统级逐字预算/截断阈值/截断标记文案，空间不足由摘要模型自行取舍（对齐 ch8-1）；`grep -rn "截断" src/main/java/com/acode/context` 不应出现针对用户消息的截断逻辑（若有，需说明为工具结果落盘预览语义）
- 摘要自身"上下文超长"重试：把摘要区历史按消息分组，丢弃最旧分组重试，最多 `3` 次；仍失败则再丢弃 `20%` 的消息组重试一次
- 熔断：摘要生成**连续失败 3 次** → 本会话 `needsAutoCompact` 恒为 false（不再自动触发）；**任一次成功压缩（含自动与手动 /compact）清零连续失败计数**，会话经 clear 钩子（清空/加载）亦清零
- 自动触发守卫：仅当「存在早于保留尾的可压缩完整轮次（非空摘要区）且压后整体估算（含 system/环境）< 触发点」才执行——历史全落在保留预算内 → `needsAutoCompact` 为 false、不产生摘要请求；"成功但压不低"的空跑不会发生，熔断只统计真正失败的触发

**"上下文超长"判定（紧急压缩用）**
- 按异常文案短语判定（`ProviderHttpClient.classify` 只透传 `error.message`，勿依赖错误码/type）：命中任一即视为超长——Anthropic 文案含 `prompt is too long`；OpenAI/DeepSeek 文案含 `maximum context length`；大小写与前后缀容错。若需按错误码精确判（`prompt_is_too_long`/`context_length_exceeded`），先扩展 ProviderHttpClient 透传 `error.code`/`type`
- 紧急压缩：正常请求被判定"上下文超长" → 强制压缩一次 → 用新历史重试原请求一次；仍失败走正常错误终止，不无限重试

**输出文案**
- 自动压缩触发前：终端出现提示行（含"压缩"字样）
- 手动 /compact：先出现"正在压缩…"；成功行含压缩前/后估算两个数字；失败行含原因且历史不变；无可压缩内容时出现"（没有需要压缩的内容）"
- `/help` 与 `/compact` 帮助文本包含 `/compact` 行
