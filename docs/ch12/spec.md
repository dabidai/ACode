# ACode 阶段十二：子 Agent 与任务分发

## 背景与目标用户
为终端编程助手的日常使用者和项目团队提供独立执行子任务的能力，减少主对话中的中间过程。已有 Skill 和 Hook 使用同一运行底座派发任务。

## 能力清单
- 主 Agent 通过统一工具派发预定义角色或继承上下文的临时助手。
- 预定义角色从空白对话开始，使用自己的系统指引；临时助手复制父历史和环境。
- 加载项目、用户和内置定义，按接近项目的优先级覆盖，坏文件产生告警而不阻断启动。
- 提供探索、规划、通用和可选验证角色，允许任务级命名与定义式模型覆盖。
- 工具白名单、黑名单和父级活动范围同时限制模型请求与实际执行。
- 子任务使用独立权限追踪，保留父级规则与路径边界，未明确授权的确认请求直接拒绝。
- 子任务同步执行到最终回复，错误、取消与轮数耗尽作为结果回传父 Agent。
- 子任务流式文本和工具事件在内部消费，界面只展示父级工具卡片和最终结果。
- 子任务不能通过工具、Skill 或 Hook 再创建子任务。
- Skill 的独立执行支持历史选择、模型和工具限制，结果不激活父会话中的 Skill。
- Hook 的子任务动作复用运行底座，失败保持失败状态，子工具仍触发适用的 Hook。
- 规划状态下主模型不可见派发工具，其他委托入口同样受父级只读工具范围约束。

## 非功能要求
- 不增加第三方依赖，逻辑组件可在无终端、无真实模型条件下测试。
- 不读写真实用户目录的测试数据，不操作数据库。
- 父子对话、事件、提示队列和 Skill 状态隔离，共享模型客户端与无状态工具设施。
- 委托不自动继承父会话历史确认；派活获批不代表任意写操作获批。
- 中断传递到子任务，等待执行循环清理后恢复前台输入。
- 配置缺陷与运行错误有可观测结果，不能静默丢失失败。

## 设计骨架
定义解析与加载 → 能力过滤 → 子会话及权限装配 → 复用既有 Agent 循环 → 静默消费事件 → 结果回传。
主流程注册派发工具，Skill 与 Hook 经适配器进入相同运行底座。Hook 子作用域共享定义、动作实现和会话一次执行标记，独立持有锁与提示队列，防止同步委托死锁及消息串入父会话。

## 完成标准
定义加载、请求与执行边界、权限、隔离、取消、跨章接入及端到端派发有自动化证据；全量回归和打包通过；真实模型和终端未实跑的项目保留未勾选状态。

## Out of Scope
后台 Agent、任务管理器、并行队员协作、工作树隔离、定义热重载、插件加载实现、新增审批界面以及子任务自动记忆提取。
不承诺实际缓存命中率；报告格式由提示词约束，仍需真实模型验收。
