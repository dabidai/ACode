# ACode 阶段十三：Worktree 工作目录隔离

## 背景与目标用户
为终端助手使用者提供独立 Git 工作目录，并为后续自动任务提供可复用的生命周期管理器。当前已有前台子 Agent，本章不增加并发任务调度。

## 能力清单
- 校验名称并创建独立分支与工作树，支持从当前提交创建及经身份验证的已有目录恢复。
- 列出本项目管理范围内的工作树、分支、路径、当前标记和变更状态。
- 进入、切换和退出工作树，仅改变工具执行目录，项目设施保持原根目录，模型环境提示同步更新。
- 持久化当前工作树会话，恢复启动时校验身份；失效或损坏记录告警并安全回退。
- 默认删除保护未提交、未跟踪、忽略文件和新增提交，显式强制命令才允许丢弃。
- 记录创建来源；自动清理只处理已登记的临时工作树，手动及未知来源永不自动清理。
- 过期清理跳过活动会话、锁定工作树、新近使用目录及未推送提交，任何检查失败均保留。
- 创建后尽力复制本地设置、配置工作树专属 hooks 路径、链接依赖、复制清单声明的忽略文件。
- 通过现有分层配置自定义依赖目录与过期时间。
- 本地命令进入现有帮助与补全，不请求模型；启动恢复后异步执行一次过期清理。

## 非功能要求
- 不新增第三方依赖；Git 子进程禁交互、关闭输入、限定运行时间和输出大小，异常保留现场。
- 移除工作树前先断开其中的链接，避免 Windows Git 沿目录联接删除源目录。所有破坏性操作前验证真实路径、所属仓库、工作树注册和分支；拒绝路径穿越和链接逃逸。
- Windows 路径含空格可用，依赖链接失败尝试目录联接后告警跳过。
- 创建后设置失败互不影响，禁止覆盖工作树已有文件或改写主仓库忽略规则与共享 hooks 配置。
- 测试仅在临时目录创建仓库，不读写用户数据库，不以当前开发仓库进行生命周期实验。

## 设计骨架
配置与本地命令 → 管理器 → Git 子进程及路径验证 → 工作树与项目级元数据。
每轮工具上下文从当前会话取工作目录；命令、权限根、记忆、会话、指令仍锚定项目根。子 Agent 与 Skill 委托继承调用方工具目录，预配置 MCP 服务保持启动目录。
元数据记录基准提交和创建来源；Git 注册信息决定目录身份，元数据不能替代 Git 核验。清理与会话操作在单个管理器内串行化，活动会话记录也作为后台清理保护。

## 完成标准
临时真实 Git 仓库的生命周期、身份冲突、文件隔离、恢复、清理保护有自动化证据；配置和命令进入主流程；全量回归及打包通过。真实终端未执行的项目明确保留待验。

## Out of Scope
子 Agent 自动工作树隔离、后台 Agent、Teams、自动合并或推送、跨进程会话协调、复制未提交主工作区改动、完整 gitignore 取反语义、MCP 服务重启迁移。
